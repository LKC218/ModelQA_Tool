# 爆炸拆分与相机自适应优化 — 实施方案

> 日期：2026-09-13 ｜ 状态：**已部署上线**（buildTime 2026-09-13T13:10:26，MD5 7/7 复验一致）｜ 影响端：审核端 + 开发端（共用 shared-viewer）

## 1. 背景与问题（用户反馈）

1. **拆分不完全**：爆炸后只有顶层总成块整体平移，总成内部零件（螺栓、爪极转子等）不分离。
2. **相机不自适应**：爆炸后零件跑出视野，相机不拉远。期望：爆炸范围扩大时相机自动拉远，始终包住全部零部件。

## 2. 现状定位（根因）

代码位置：`tool/src/shared/shared-viewer.js`

| # | 现状代码 | 根因 |
|---|---|---|
| 1 | `pickExplodeUnits()`（L282）：只取根下一层子节点（唯一分组才下钻一层） | 爆炸单元只到总成层，总成内部不拆 → 拆分不完全 |
| 2 | `settleFrameAfterExplode()`（L469）：只有「定位联动」路径（`pendingFrame`）才在爆炸后取景目标零件 | 手动点爆炸按钮 / 拖滑块时相机完全不动 → 零件出视野 |

UI 层（`shared-components.js` bindViewportTools）：按钮 `setExplode(0↔1)`、滑块 `setExplode(v/100)`，均不做相机处理 → 修改收敛在 viewer 层，双端同时受益。

## 3. 方案设计

### 3.1 多级爆炸拆分

- **单元收集**（重写 `pickExplodeUnits`）：
  - L1 = 根下一层含网格子节点（沿用现有规则，含单分组下钻）；
  - L2 = 若某 L1 单元内部还有 **≥2 个** 含网格直接子节点，则将这些子节点一并纳入爆炸单元（螺栓等从总成中弹出）；
  - 约束：**层级深度 2 层**；**单元总数上限 40**（超限停止纳入 L2），防止深模型碎片化；
  - 输出顺序：L1 在前、L2 在后（保证标注 `slice(0, LABEL_LIMIT)` 行为与现状基本一致）。
- **级联偏移**（调整 `buildExplode`）：
  - L1 单元：沿用现有算法——「单元中心 → 模型整体中心」反向，距离 = 原距 + `gap(0.18×对角线)`；
  - L2 单元：方向 = 「子件中心 → 所属总成中心」反向（同向退化时继承总成方向），距离 = 原距 + `gapInner(0.07×对角线)`；
  - 偏移一律换算为各自父节点本地坐标（沿用现有矩阵求逆逻辑），父总成外移 + 子件再外移天然级联。
- **判定辅助**：`unitSet.has(unit.parent)` 判定 L2（L2 的父节点必是 L1 单元），无需显式深度标记。

### 3.2 爆炸后相机自适应取景

- **机制**：复用现有 `frameGoal` 指数趋近视点（无瞬跳），新增 `frameExploded()`：
  - 包围盒 = 爆炸后整体 `Box3.setFromObject(explodeRoot)`；
  - 保持当前视线方向，仅调整距离与中心：距离 = `2.8 × (对角线/2)`（含标注与边缘余量，保证视锥纵向覆盖）。
- **触发**：新增标志 `frameAfterExplode`：
  - `setExplode()` 内：`frameAfterExplode = (target > 0)`（按钮/滑块 UI 路径自动生效）；
  - `tickExplode()` 动画到位（factor === target）→ `settleFrameAfterExplode()`：有 `pendingFrame`（定位联动）→ 维持现有「只取景目标零件」行为并清标志；否则标志为真 → 对爆炸后整体包围盒取景一次；
  - 滑块拖动中 target 持续变化 → 不触发；松手后最后一次 settle 取景一次。按钮路径动画约 1s 后取景一次。
- **复位**：`watchModelRoot()` 切模型时清 `frameAfterExplode` 与 `pendingFrame`（后者已有）。
- **定位联动兼容**：`locateNode()` 触发的自动爆炸仍优先取景被定位零件（`pendingFrame` 优先级高于整体取景），行为不回归。

### 3.3 非目标（本期不做）

- 不做错峰级联 / 缓动曲线更换 / 旋出自转（上期讨论项，另行排期）；
- 不改 UI 层任何代码；不改标注（`labelTargets` 复用新单元集合，LABEL_LIMIT 兜底）；
- 不处理用户拖拽相机中断取景的抢占逻辑（保持现状）。
