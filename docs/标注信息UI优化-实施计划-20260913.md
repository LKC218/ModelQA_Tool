## 2. 参考案例调研结论（2026-09-13 检索）

### 2.1 Sketchfab 标注（行业事实标准）
- **编号圆点 + 点击弹出卡片**；标注按数序排列，底部有前后导航条，支持 Autopilot 自动巡览、J/K 键切换；
- hover 标注菜单按钮时显示全部标注（按需浮现，不常驻刷屏）。
- **可借鉴**：编号系统、按需浮现思想。**不照搬**：点击卡片（本工具右侧已有「当前零件/问题记录」面板，信息卡冗余）、自动巡览（审核场景不需要）。

### 2.2 CAD 技术插画 / 爆炸图规范（SolidWorks/NX 手册惯例）
- 引线**细（1-2px）、低饱和色、端点小圆点或箭头、避免硬折角**；引线不得危险交叉，复杂装配**成组归拢到图例/BOM**；
- **编号气泡与 BOM 表交叉引用**是核心可读性机制；标签层次分明、防重叠；深度靠阴影/透视/色差区分。
- **可借鉴**：引线端点圆点、编号对应侧栏树、防重叠。

### 2.3 three.js 社区技术方案（遮挡与避让）
- **遮挡淡出**：标签→相机连线 raycast 与模型求交，相交即判定被遮挡 → 加 `.hidden` class 淡出（博客园/Hijacku 方案）。替代方案为 NDC z 动态 z-index、法向点积淡入淡出。**成本控制**：raycast 降频（相机静止后算一次，运动中节流 ~100ms），24 标签 × 70 mesh 场景无压力。
- **屏幕空间避让**：CSS2D 元素是真实 DOM，可 `getBoundingClientRect` 检测两两重叠，通过 element 的 `translate` 屏幕偏移错开（不动 3D 锚点），配 150ms 过渡防跳动。
- 性能红线：CSS2D 每帧更新全部元素，>200 元素 DOM 开销陡增——本场景 24 个，安全。

## 3. 痛点 → 改动映射（分级，供勾选范围）

### P0 视觉升级（纯 CSS + 小改 buildLabels）
1. **芯片重设计**：编号徽标（`<i>` 圆形序号，accent 底白字）+ 零件名；背景改「高不透明 + 细描边 + 柔和投影」的层级卡（浅色/深色主题双套校验）；hover 显示完整名（`title` 属性 + max-width 放宽至 220px）。
2. **引线精致化**：1px、低饱和主题色、**端点小圆点**（THREE.Sprite 或 Points，随引线色），替代裸线头。

### P1 实用性修复（shared-viewer.js 核心逻辑）
3. **遮挡淡出**：`updateLabelAnchors` 内按节流触发 raycast（锚点→相机），被模型遮挡的芯片加 `.is-occluded`（opacity 0.25 + 轻微缩小，保留存在感，不完全隐藏——审核场景不丢信息），相机静止后收敛一次。
4. **屏幕空间避让**：渲染循环内检测芯片两两屏幕 AABB 重叠（>40% 才触发，轻微重叠不管），对后者做 translateY 屏幕错开 + 150ms 过渡；结果缓存，相机静止后收敛。

### P2 交互联动（涉及 reviewer-implementation.js，改动面较大）
5. **编号 ↔ 侧栏树联动**：标签 hover → 「模型层级」树对应节点高亮；标签点击 → 复用 `locateNode` 定位取景。viewer 暴露 `onLabelHover/onLabelClick` 回调注册。

### 明确不做
- Sketchfab 式点击信息卡（右侧面板已有）、标注拖拽、Autopilot 巡览、快捷键导航、引线路径规划（防交叉布局算法——爆炸布局已保证单元分离，重叠概率低，避让已够用）。
