## 1. 背景与根因

用户反馈：爆炸视图切换时相机拉远**生硬**（滑块/按钮拉远直接切换不流畅）。

根因两条（代码 `tool/src/shared/shared-viewer.js`）：
1. **爆炸全程相机不动，settle 后一次性取景**：`tickExplode()` 只在 `explodeFactor === explodeTarget` 时经 `settleFrameAfterExplode()` 触发 `frameExploded()`——爆炸动画期间（约 1s）与滑块拖动期间相机原地不动，结束后突然追，两段式割裂；
2. **收敛曲线太硬**：`tickFrame()` 用 `lerp(goal, 0.16)`——起步速度最大（突跳）、到位急停，无缓入缓出。

相关机制（现行为，勿破坏）：
- `frameAfterExplode` 标志：`setExplode()` 内按 `target > 0` 置位；`settleFrameAfterExplode()` 消费；`locateNode()` 定位联动时显式清 false（定位取景走 `pendingFrame`，优先级高于整体取景）；`watchModelRoot()` 切模型复位时清 false。

## 2. 改动清单（仅 shared-viewer.js，两处小改）

### 2.1 爆炸全程连续取景
`tickExplode()` 的 `applyExplode(explodeFactor);` 之后、settle 判断之前插入：
```js
    /* 手动爆炸全程连续取景：相机同步跟随爆炸范围变化，避免动画结束后一次性猛拉 */
    if (frameAfterExplode && explodeTarget > 0) frameExploded();
```
- 每帧基于当前 factor 的包围盒重算 `frameGoal` → 相机与爆炸范围同步平滑退远，滑块拖动中实时跟随；
- settle 时已有的 `frameExploded()` 调用保留（终态精确收敛，冗余无害）；
- 性能：每帧 `Box3.setFromObject(explodeRoot)` 仅 70 mesh × 8 角展开，微秒级。

### 2.2 收敛曲线放缓
`tickFrame()` 中两处 `lerp(..., 0.16)` → `lerp(..., 0.10)`。

### 2.3 明确不做
- 不改定位联动取景逻辑、不改爆炸动画本身（0.16 指数趋近）、不加用户拖拽相机时的取景抢占保护（保持现有行为）。
