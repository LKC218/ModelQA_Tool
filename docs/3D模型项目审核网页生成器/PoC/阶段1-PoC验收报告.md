# 阶段 1 PoC 验收报告

## 已实现

- 单个 GLB 通过 File API 读取并内嵌为 Base64，结果 HTML 完全自包含。
- GLB JSON/BIN 解析：节点名称、节点层级、网格、POSITION、索引与三角形统计。
- `file://` 页面中的 WebGL 模型显示、层级树选择与当前节点琥珀高亮。
- Issue 表单绑定 `persistentNodeId`、节点路径和节点名称，并可写入一条 Issue。
- 导出采用固定运行时模板与当前数据重新序列化；结果页可再次导出。
- 页面明确单 HTML 20 MB 建议阈值和 ZIP 主动选择解压目录交互边界。

## 本地验证记录

静态自动检查已完成：主页面脚本通过 Node 语法检查；页面外部资源引用数为 0；包含 `JSON.stringify(data)` 固定模板序列化路径；包含 `persistentNodeId` 字段路径。当前执行环境的浏览器安全策略拒绝自动化打开新增 `file://` 文件，因此没有把浏览器冒烟检查冒充为通过。

## 阻断风险

1. 当前 PoC 使用最小 WebGL 渲染器，未覆盖材质、纹理、动画、蒙皮和所有 GLB accessor 类型。
2. 节点持久标识优先读取 `node.extras.persistentNodeId`，缺失时暂以节点名或 `node-{index}` 兜底；这只能支持 PoC 当前文件，不能承诺跨版本稳定定位。
3. 大于 20 MB 的单 HTML 仅给出 ZIP 交付提示，ZIP 审核器与目录选择加载属于 MVP 范围。
4. Chrome/Edge、清缓存重开和 10/30/50 MB 性能仍需在目标审核电脑上实测并回填本报告。

## 阶段结论

代码路径已具备 PoC 验证条件，但在完成上表待验证项前，不能宣布 PoC 通过，也不得进入 MVP。
