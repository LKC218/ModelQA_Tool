# 审核填写流与结论强化 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。  
> 背景先读：`docs/apps-code-map.md`、`docs/3D模型项目审核网页生成器/实施方案/UIUX重构实施计划-V1.0.md`（骨架与 Token 已落地，本计划只动审核端内容层与结论展示）。

## 1. 背景与问题

ModelQA 审核端（`tool/src/reviewer-implementation.js`）右栏现状是「三段堆表单」：

| 区块 | 现状 | 痛点 |
|---|---|---|
| 当前模型审核 | `<select id="model-status">` + 说明 | 结论藏在下拉里，过没过不能一眼读出；交接开发方不直观 |
| 问题定位 | 当前零件 + 高级信息 + 更换零件 | 与填写割裂，占一整块 |
| 审核问题 | 状态下拉 + 文本 + 「添加模型/零件问题」双按钮 + 清单 | 步骤多、状态弱、删除无撤销 |

讨论结论（GLM 三轮 + 主流对照）：

1. 从「表单式填写」改为 **「状态即按钮、卡片即结论、写读分离」**。
2. 大方向符合主流（Jira/Linear/GitHub 最小必填、上下文自动继承、严重度置顶、toast 撤销）；需防坑 2 处（空文通过滥用、徽章与整卡点击冲突）。
3. **模型结论必须多处同色可见**，核心一刀是 **3D 视口 HUD 大徽章**，方便审核交接给开发方。

## 2. 目标与非目标

**目标**

1. 右栏填写路径缩短：选零件 → 点三态 →（可空）记入，主路径约 2 下。
2. 通过/待改/阻断/未审 **四态在视口、列表、右栏、顶栏同色同步**，开发方一眼可判。
3. 零件问题与模型结论不打架（建议结论 + 一键采用）。
4. 删除可后悔（toast + 撤销）；状态可改而不重录。

**非目标**

- 不改数据结构：`schemaVersion: 2`、`review.byModel`、导出 JSON 字段与 ZIP 目录不变。
- 不引入框架、不改 Vite/esbuild 构建、不动 3D 视口相机/拾取逻辑。
- 不做快捷标签（用户明确否决）。
- 不做移动端；开发端 UI 仅在 Token 允许范围内共用 `.segmented` 时顺带受益。

## 3. 设计方向（已确认）

### 3.1 右栏目标骨架（写读分离）

```
┌─ 右栏 ~360px ─────────────────────────────┐
│ 模型结论  [✓通过] [⚠待改] [⛔阻断]          │  ← 与清单同色系
│ 审核要求（只读，可折叠）                     │
│ 说明（可空）                                │
├─ 记录卡（独立浮卡，非表单堆）────────────────┤
│ 记录对象：● 零件名  [改记整个模型]            │  ← 跟选中零件
│ [✓通过] [⚠待改] [⛔阻断]   默认：待改        │
│ 描述这个问题（可空）                         │
│                     [ ✓ 记入 ]              │  ← 唯一主按钮
├─ 审核问题 · 2通过 · 1待改 · 1阻断 ──────────┤
│ [⛔] 零件名   焊盘缺失 · 已定位 →      [×]  │
│ [⚠] 模型     丝印方向不符             [×]  │
└────────────────────────────────────────────┘
```

- 「问题定位」整块撤掉：当前零件并入记录卡；节点路径/ID 收进现有「高级信息」折叠，仅在需要时展开。
- 「更换零件」语义由视口/树重新选择承担，不再单独占按钮位（可保留极小的「清除选择」链接）。

### 3.2 结论可见性矩阵（交接开发方）

| 位置 | 表达 | 何时刷 |
|---|---|---|
| 3D 视口 HUD | 模型名旁 **大号状态徽章**（色底 + 图标 + 文字） | 换模型、改 modelStatus |
| 右栏结论 | `.segmented` 三态按钮（+「待审核」未选中中性态） | 同上 |
| 课程卡徽章 | `已审/总数` 旁迷你三色条或当前模型状态点 | 渲染课程条时 |
| 模型导航行 | 色点 + 短文案（通过/待改/阻断，未审不写文案） | `rowLeadingHtml` / 模型列表 |
| 顶栏进度 | 替代纯 `12/18` 为三色统计：`2通过 · 1待改 · 1阻断` | 每次 renderModels |

**视觉语义**

| 状态 | Token | 表达 |
|---|---|---|
| pending 未审 | `--dim` | 灰点 / 中性描边，带「未结论」感，不得像通过 |
| pass 通过 | `--success` | 绿 + ✓，可略收音（审核完成态） |
| risk 待改 | `--accent` | 琥珀 + ⚠，中等强调 |
| block 阻断 | `--danger` | 红 + ⛔，最强强调（HUD/顶栏可加重） |

原则：阻断余光可跳；通过可安心跳过；未审不可误读为没问题。色盲：**图标 + 文字 + 颜色三重冗余**；未选中分段按钮保持中性描边，禁止「未选中就上红绿」。

### 3.3 交互规则

| 项 | 规则 |
|---|---|
| 三态分段 | 默认中性描边；选中填色 + 图标+文字常驻；键盘 Tab/方向键可切 |
| 模型结论 | 同一套 `.segmented`；无「待审核」第四钮，保持默认中性 = 未结论；可提供次按钮「标为待审核」 |
| 范围自动 | 选中零件 → `scope=node`；未选中 → `scope=model`；记录卡顶一键「改记整个模型」切换 |
| 空文记入 | 允许；若状态为 risk/block 且文案为空，记入后 toast「已记入，建议补一句原因」（不阻断） |
| 建议结论 | 由 `issues` 推导：含 block→阻断；仅 risk→待改；全 pass 或空→通过；展示在结论区「建议：× · 一键采用」，可忽略 |
| 清单排序 | block → risk → pass；稳定排序（同状态保持录入序） |
| 清单行 | 左 4px 色条 + 状态图标；对象名 + 摘要 + 定位箭头；悬停显现删除 |
| 改状态 | 点状态徽章 → **弹三选一小菜单**（非循环点击）；`stopPropagation`，避免误触定位 |
| 删除 | 底部 toast「已移除 · 撤销」，约 5s；撤销恢复原 index |
| 点击整卡 | 仍 `locateIssue`；徽章热区独立 ≥28px |

### 3.4 明确不做

- 快捷标签条。
- 点零件自动写入一条 issue。
- 改导出 schema / 开发端结果页重构（开发端对齐徽章 Token 列为 P3 可选，本计划不交付）。

## 5. 分阶段任务与验收

> 每阶段结束：`cd tool && npm run build` 通过，并用 `reviewer-preview` 或导出的审核器 HTML 冒烟。  
> 阶段可独立提交；禁止破坏导出 JSON 字段。

### 阶段 P0：状态强化 + 结论可见（必做）

1. 实现 `.segmented` 三态控件（通过/待改/阻断），模型结论与 Issue 记录状态共用。
2. 删除右栏 `#model-status` / `#issue-status` 原生 select 的交互依赖（DOM 可移除），写入仍调用原 `modelStatus` / `issueStatus` 字段。
3. 3D 视口 HUD：模型名旁大徽章，四态同色；`loadModel` / 改结论 / `renderReview` 时刷新。
4. 模型导航行：色点 + 短文案；课程卡保持 `已审/总数`，可选加当前模型状态点。
5. 顶栏进度改为三色统计（可保留 `已审/总数` 作 title 或副文案）。
6. 清单卡片：左色条 + 状态图标 + 文字加大一号；徽章点击弹三选一菜单；整卡点击定位不变。

**验收**

- 不打开下拉即可从 HUD / 列表 / 右栏读出当前模型过没过。
- 色盲语义：灰度截图仍能靠图标+文字区分四态。
- 导出 JSON 中 `modelStatus` / `issues[].issueStatus` 取值仍为 `pending|pass|risk|block`，无新枚举。

### 阶段 P1：填写路径 + 写读分离（体验跃升）

1. 右栏重排为「结论区 + 记录卡 + 问题清单」；移除独立「问题定位」大区块。
2. 记录对象自动跟随选中零件；一键切「整个模型」；未选零件时明确提示并默认 model。
3. 空文可记入；risk/block 空文时 toast 建议补因。
4. 「添加模型问题 / 添加零件问题」双按钮合并为唯一「记入」。
5. 清单按 block→risk→pass 排序；删除改 toast + 撤销。
6. 建议结论条 + 一键采用（写 `modelStatus`，不自动覆盖已人工选过的状态除非点采用）。

**验收**

- 主路径：选零件 → 点「待改」→ 直接记入（无字）→ 出现在清单顶部区。
- 范围在记录卡头部可见，且与实际写入的 `scope` 一致。
- 删除后 5 秒内可撤销，撤销后顺序与原 index 一致。
- 切换模型不会残留上一模型的记录卡草稿文字（或明确清空策略并在文档写死：建议清空）。

### 阶段 P2：收尾与文档

1. 强调层级微调（通过略收、阻断略放）；`prefers-reduced-motion` 复查。
2. 空态、焦点环、键盘操作分段控件。
3. 更新 `docs/apps-code-map.md`；如有模块就近说明则同步。
4. 全流程冒烟：开发端导出单 HTML/ZIP → 审核端打开 → 逐模型审核 → 定位零件 → 改状态 → 撤销删除 → 导出结果 JSON。

**验收**

- 离线审核器样式完整、无控制台报错。
- 与骨架重构计划（UIUX V1.0）无样式打架；共享类名不复制粘贴。

### 阶段 P3（可选，本计划默认不交付）

- 开发端读取审核结果时，模型列表对齐同一套结论徽章与排序。

## 6. 实现要点（防坑）

1. **徽章热区**：菜单/徽章按钮 `event.stopPropagation()`，避免冒泡到整卡 `locateIssue`。
2. **建议结论 vs 人工结论**：仅在「建议」层提示；只有点「采用」才写 `modelStatus`；人工已改过后不要每帧强制弹建议。
3. **空文通过**：导出后开发端可能只有状态无描述——用 toast 软引导，不在 `addIssue` 硬 return。
4. **HUD 徽章不挡拾取**：`pointer-events: none` 在容器，仅按钮可点；避免盖住 viewer-toolbar。
5. **状态菜单**：挂 `pointerdown` 外点关闭 + `Escape`，与现有 course-menu 模式一致。
6. **运行时体积**：样式继续走 `__AN_SHARED_CSS__` + reviewer 独有小段，禁止整段复制 shared。

## 7. 优先级总表

| 级 | 内容 | 解决 |
|---|---|---|
| P0 | 三态分段 + HUD 大徽章 + 列表/顶栏同色 + 清单色条/图标/徽章菜单 | 状态弱、交接不直观 |
| P1 | 写读分离 + 范围自动 + 空文可记 + toast 撤销 + 建议结论 | 路径长、状态不一致 |
| P2 | 强调层级、键盘/动效、文档与全量冒烟 | 打磨与闭环 |
| P3 | 开发端结果页对齐 | 跨端一致（可选） |

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 旧用户习惯 select | 分段更直观；保留四态语义，无学习新枚举 |
| 空文记录变多 | risk/block 软提示；不阻断高频「通过」 |
| 点错状态 | 徽章菜单而非循环点击；toast 撤销仅针对删除，状态可在菜单内改回 |
| HUD 与工具条重叠 | 布局放在 HUD 行内 flex，不绝对定位盖工具条 |
| 与 UIUX 骨架类名冲突 | 新增类用审核端前缀或落入 shared 的明确组件名（`.segmented`） |

## 9. 验收清单（合并）

- [ ] 右栏无结论/问题状态下拉，改为分段按钮与记录卡。
- [ ] 视口 HUD 常驻模型结论徽章，与 `modelStatus` 同步。
- [ ] 顶栏三色统计；模型行色点+短文案。
- [ ] 选中零件自动 node 范围；可切整个模型；唯一「记入」。
- [ ] 空文可记入；清单纯文；排序 block→risk→pass。
- [ ] 徽章弹菜单改状态；删除 toast 可撤销。
