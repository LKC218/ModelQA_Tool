# 多模型审核工具化实施计划-V1.0

## 一、目标

为 `Model/AN-模拟电路实训室` 等项目提供本地离线的多模型审核闭环：开发者配置多个 GLB，导出审核包；审核者查看模型、定位节点、填写 Issue，并导出审核结果。

## 二、正式版运行边界

正式版必须拆分为两个独立入口，不能把开发者编辑端和审核者端作为同一个可双击页面交付：

| 入口 | 启动方式 | 使用者 | 主要职责 |
| --- | --- | --- | --- |
| 开发者编辑端 | 必须启动本地服务器后访问 | 开发者 | 导入多个 GLB、编辑项目、保存草稿、生成审核包 |
| 审核者端 | 打开导出的单 HTML，或打开审核器后选择 ZIP 解压目录 | 审核者 | 查看模型、定位节点、填写 Issue、导出结果 |

开发者编辑端使用 Vite 本地开发/生产服务器，允许使用 File API、项目草稿和目录选择能力；审核者端必须保持离线，不依赖开发者服务器、CDN、浏览器缓存或外部资源。

## 三、产品形态

### 1. 开发者编辑端

- 创建项目并填写项目编号、名称、版本、制作人和备注。
- 批量导入多个 GLB，设置模型名称、排序、审核要求和关键节点。
- 查看模型层级，检查 `persistentNodeId` 是否可用。
- 预览审核者页面并生成审核包。

### 2. 审核者端

- 在同一工作台中切换项目内多个模型。
- 使用 Three.js 查看、旋转、缩放、适配和线框查看模型。
- 通过层级树或画布点击选中并高亮零件。
- 填写模型结论和 Issue，导出审核结果。

两端共用固定设计令牌和工作台布局，只通过权限隐藏编辑能力。

## 四、项目包格式

```text
AN-模拟电路实训室/
├─ project.json
├─ models/
│  ├─ 万用表.glb
│  ├─ 直流稳压电源.glb
│  └─ 二极管.glb
├─ review/
│  └─ issues.json
└─ 审核器.html
```

`project.json` 保存项目和模型清单；`issues.json` 保存审核结果。模型文件保持独立，单 HTML 导出时才转为内嵌数据。

## 五、核心数据约束

每个模型至少包含：

- `modelId`
- `fileName`
- `version`
- `sortOrder`
- `requirement`
- `persistentNodeId`

每条 Issue 必须绑定：

- `projectId`
- `modelId`
- `modelVersion`
- `persistentNodeId`
- `nodePath`
- `nodeName`
- `issueStatus`
- `issueText`
- `createdAt` / `updatedAt`

`persistentNodeId` 是跨版本定位优先依据。临时 UUID 只允许用于当前运行时对象，不能作为长期唯一标识。缺少稳定标识时必须提示人工确认。

## 六、技术方案

- 开发者编辑端：Vite + JavaScript/TypeScript，本地服务器启动，负责项目编辑、草稿和打包。
- 审核者端：固定运行时模板，构建为自包含 HTML 或 ZIP 审核器。
- 三维查看：Three.js、`GLTFLoader`、`OrbitControls`、`Raycaster`。
- 开发者数据：`project.json`，后续可增加 `.anreview.json` 草稿。
- 单 HTML：固定运行时模板 + 项目数据 + 分块 Base64 GLB。
- ZIP：`审核器.html` + `project.json` + `models/` + `review/`。
- 禁止依赖 CDN、服务器、浏览器缓存和外部资源。

## 七、交付策略

| 内嵌后资源量 | 交付方式 | 规则 |
| --- | --- | --- |
| 不大于 20 MB | 单 HTML | 可直接 `file://` 双击审核 |
| 20–50 MB | 优先 ZIP | 审核者主动选择解压目录 |
| 大于 50 MB | 强制 ZIP | 不承诺单 HTML 内嵌 |

最终阈值必须通过目标电脑实测确认。ZIP 在 `file://` 下不能自动读取同级文件，必须提供“选择审核包文件夹”入口。

## 八、实施阶段

### 阶段 1：双入口基础闭环

- 开发者编辑端服务器入口和项目清单。
- 审核者自包含运行时入口。
- 多 GLB 导入和项目清单。
- Three.js 查看器、层级树和节点高亮。
- Issue 绑定 `persistentNodeId`。
- 单 HTML 导出和结果 HTML 再导出。

验收：开发者端必须通过本地服务器打开；至少完成一个包含两个模型的项目审核闭环；审核者端可脱离服务器打开导出包。

### 阶段 2：审核包与草稿

- `.anreview.json` 草稿保存和恢复。
- 单 HTML 容量检查。
- ZIP 审核包生成。
- 审核者主动选择解压目录并加载多个 GLB。

验收：关闭浏览器、清空缓存后，单 HTML 和 ZIP 均可恢复模型与 Issue。

### 阶段 3：审核增强

- 部件隐藏、独显和截图。
- Issue 视角恢复。
- 模型结论、项目总体结论和复审状态。

### 阶段 4：性能与规模化

- 10 MB、30 MB、50 MB GLB 性能测试。
- Chrome、Edge 兼容性测试。
- 大项目懒加载、资源释放和内存风险控制。

## 九、阻断条件

- `file://` 下模型无法加载或层级无法解析：停止后续阶段。
- 导出结果依赖原 HTML、缓存或服务器：停止后续阶段。
- Issue 无法稳定绑定模型和节点：停止版本迁移设计。
- 单 HTML 超过实测内存阈值：切换 ZIP，不继续扩大内嵌上限。
- 开发者端可在无服务器情况下被误当作正式编辑入口：停止发布并修正文档、启动脚本和入口提示。

## 十、当前落点

正式工具入口位于仓库 `tool/`。后续应拆分为开发者服务器入口和审核者导出运行时；PoC 页面保留在 `PoC/` 作为验证基线。本计划不覆盖云端协作、多人权限和自动版本迁移。
