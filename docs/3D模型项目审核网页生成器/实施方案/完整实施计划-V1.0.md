# 3D模型项目审核网页生成器-完整实施计划-V1.0

## 1. 目标与结论

建立本地离线的课程 3D 模型审核工具。一个课程项目生成一个审核包，审核人可查看多个模型、定位零件、填写结构化问题，并把结果回传给开发人员。

本项目采用两类交付包：

| 资源总量 | 交付方式 | 适用范围 |
| --- | --- | --- |
| 不大于 20 MB | 单 HTML | 小项目，便于单文件发送与双击审核 |
| 大于 20 MB 且不大于 50 MB | 优先 ZIP | 中型项目，避免 Base64 导致的内存压力 |
| 大于 50 MB | ZIP | 强制使用，模型文件不嵌入 HTML |

单 HTML 的最终阈值必须以 PoC 在目标审核电脑上的实测结果为准。ZIP 包在 `file://` 下不能依赖 HTML 自动读取同级 GLB；审核人需在页面中主动选择解压后的审核包文件夹，或后续另行引入本地启动器。

## 2. 用户与闭环

### 开发人员

1. 创建项目并填写项目基本信息。
2. 导入多个 GLB，填写每个模型的要求、排序与关键零件标识。
3. 检查模型层级和关键零件的稳定标识。
4. 根据资源规模生成待审核 HTML 或 ZIP 审核包。
5. 接收审核结果，按 Issue 定位模型与零件。

### 审核人员

1. 打开待审核 HTML，或打开审核器后选择 ZIP 解压目录。
2. 逐个查看模型、层级与零件。
3. 对模型填写通过或待修改，并将 Issue 绑定到当前零件。
4. 填写图片、链接、项目总体意见。
5. 导出审核结果 HTML 或审核结果 ZIP。

## 3. 固定模板规范

审核端与开发端共用一套工作台模板，只改变权限、操作和数据。

| 项目 | 固定规则 |
| --- | --- |
| 背景 | 深黑 `#000000`，使用低对比网格纹理 |
| 面板 | 石墨灰 `#1c1c1e`、卡片 `#2c2c2e` |
| 主强调色 | 琥珀金 `#f3b44e`，只用于主操作、当前选中与关键焦点 |
| 状态 | 通过绿色、待配置或风险黄色、不通过红色 |
| 容器 | 顶栏与悬浮工具栏使用半透明磨砂材质；卡片 10 至 12 px 圆角 |
| 桌面布局 | 顶部栏 + 左侧导航/树 + 中央工作区 + 右侧属性/审核面板 + 底部进度栏 |

所有颜色、间距、圆角、阴影均从设计令牌读取。项目数据不得携带自定义 CSS；模板修改必须增加 `templateVersion`，旧包继续使用原模板。

## 4. 开发者工具信息架构

开发者端固定为三个步骤：

### 步骤一：项目配置

- 项目编号、名称、版本、制作人、备注。
- 显示必填项完成度和草稿状态。
- 导出内部 `.anreview.json`，用于继续编辑和故障恢复。

### 步骤二：模型配置

- 左侧显示项目模型列表和状态。
- 中央显示当前模型、层级树和基础查看控制。
- 右侧编辑模型名称、制作要求、排序、规格和关键零件信息。
- 关键零件必须配置 `persistentNodeId`；未配置时阻止承诺跨版本自动定位。

### 步骤三：审核包生成

- 汇总模型、附件、预计文件体积和导出风险。
- 根据总资源量给出单 HTML 或 ZIP 建议。
- 生成前执行项目配置、模型状态、资源体积与安全输入校验。
- 提供审核端预览与最终导出。

审核端保持三栏结构，但移除项目编辑入口，只提供查看、审核、Issue 与导出结果。

## 5. 数据与稳定定位

核心类型包括：`Project`、`ReviewModel`、`ReviewIssue`、`ProjectReview`、`NodeReference`、`CameraView`、`PackageManifest`。

每个 Issue 记录：

- 项目、模型与模型版本。
- `persistentNodeId`、带同级序号的节点路径、名称、节点类型。
- 创建时的相机位置、观察目标和后续爆炸值。
- 问题说明、图片、链接、状态、创建和更新时间。

跨版本定位优先使用 `persistentNodeId`。UUID 只用于当前 GLB，不能作为跨版本依据；若缺少稳定标识，只允许候选匹配并要求人工确认。

## 6. 技术架构

### 生成器

React、TypeScript、Vite、IndexedDB、File API。负责编辑项目、暂存草稿、导入资源和生成审核包。

### 审核运行时

Three.js、GLTFLoader、OrbitControls、Raycaster。负责模型查看、层级解析、双向选择、聚焦和高亮。

### 导出器

独立运行。单 HTML 采用“固定运行时模板 + 内嵌项目数据 + 分块 Base64 二进制数据”；审核结果重新由当前领域数据组装生成，不能依赖浏览器缓存或读取原 HTML 文件。

### ZIP 审核包

包含 `审核器.html`、`project.json`、`models/` 和 `review-assets/`。模型保持独立二进制文件，结果包只更新项目数据与附件。

## 7. 阶段任务

### 阶段 0：视觉与工作流验证

- 已完成审核端视觉预览。
- 完成开发者工具第一版验证页。
- 确认两端共享的模板、颜色和布局方向。

### 阶段 1：阻断性 PoC

1. 内嵌单个 GLB 的单 HTML 离线运行。
2. `file://` 下加载、层级解析、选中高亮。
3. 写入一条 Issue 后导出新的完整 HTML。
4. 清理缓存、复制到另一台电脑后重新打开。
5. 实测 10 MB、30 MB、50 MB 模型的打开与导出性能。

PoC 任一阻断项失败，暂停 MVP，先调整交付架构。

### 阶段 2：MVP

1. 项目配置与 `.anreview.json` 草稿。
2. 多 GLB 导入、懒加载与资源释放。
3. 层级树、3D 双向选择、聚焦与高亮。
4. 模型结论、Issue、图片、链接与项目总审核。
5. 单 HTML 生成、审核结果再次导出。
6. ZIP 审核包与目录选择加载。

### 阶段 3：审核增强

- 部件隐藏、独显、截图、恢复问题视角。
- 爆炸图和人工偏移配置。
- 问题解决、复审和版本继承。

### 阶段 4：规模化能力

- 大型项目性能优化、批量项目清单、审核看板与报告。
- 云端协作、权限、通知仅在本地闭环稳定后评估。

## 8. 验收标准

### 第一版验证页

- 开发人员能完整浏览项目配置、模型配置、审核包生成三个工作区。
- 模板风格与审核端预览一致。
- 能清楚理解单 HTML 和 ZIP 的使用边界。

### PoC

- 断网双击打开单 HTML，模型、树、选择与审核数据正常工作。
- 导出结果后，关闭浏览器并清空缓存，重开结果文件仍有模型与审核数据。
- 在 Chrome 和 Edge 的目标 Windows 电脑上通过。

### MVP

- 完成一个两模型项目的生成、审核、问题绑定、结果回传闭环。
- 问题可回到对应模型和零件。
- 图片、链接、总体结论完整保留。

## 9. 风险与边界

- 单 HTML 不承诺支持任意规模资源；超过阈值强制 ZIP。
- ZIP 在无本地服务的前提下需要用户显式选择审核包目录。
- 模型层级没有稳定标识时，不承诺跨版本自动定位。
- 首版不做爆炸图、版本自动迁移、多人协作与云端能力。
- 所有文字以安全文本渲染，链接仅允许 `http:` 和 `https:`，图片须实际解码并限制大小。

## 10. 下一步

确认开发者工具第一版的界面和流程后，立即进入阶段 1 的单 GLB 自包含 HTML PoC。PoC 通过后才创建正式工程和开始 MVP 开发。
