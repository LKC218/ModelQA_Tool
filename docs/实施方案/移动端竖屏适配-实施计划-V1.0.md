# 移动端竖屏适配 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。
> 背景先读：`docs/apps-code-map.md`；适配现状与问题清单见 2026-09-14 会话审核结论（P1 作用域泄漏 / P2 三件套 / P3 横屏预算）。
> 已拍板：编辑端走**方案 A**（≤600 复用 mobile-tabs+抽屉模式）；竖屏分档 **≤600 Sheet / 601–900 分栏 / >900 现状**；拖拽 snap 作为 **2b 增强期**（先上点按两态）。

## 1. 目标与非目标

**目标**

1. P1 根治：移动端「形态规则」按 `.is-editor` / `.is-reviewer` 作用域限定，编辑端窄窗不再出现「侧栏永久不可达 + footer 丢失」的半适配状态。
2. P2 清零：toolbar safe-area 双重补偿、编辑端 viewport 缺 `viewport-fit=cover`、编辑端触屏 hover 不可达控件。
3. 审核端竖屏升级：≤600 用 Bottom Sheet 两态（peek 摘要 + half 编辑），601–900 上下分栏。
4. 编辑端 ≤600 补齐 mobile-tabs + 抽屉（方案 A），手机可浏览课程模型/设置。
5. 3D 触摸增强：统一手势配置、双击复位相机、`visibilitychange` 停渲染。

**非目标**

- 不做移动端「全功能编辑」（编辑端手机只保证浏览/查看，编辑仍以 PC 为主）。
- 不改断点以外的桌面布局与既有导出产物结构。
- 不引入第三方手势/组件库（KISS，原生 pointer + CSS 实现）。
- 不回溯修改 `tool/output/` 历史产物。

## 3. 分档形态设计（拍板）

| 视口 | 审核端 | 编辑端 |
|------|--------|--------|
| ≤600 竖屏手机 | **Bottom Sheet 两态**：peek（48px 摘要条常驻：模型名+结论+问题数）/ half（55dvh 编辑）；3D 常驻上方 | 方案 A：mobile-tabs（模型/设置）+ 底部抽屉（复用审核端已验证模式） |
| 601–900（平板竖屏/窄窗） | **上下分栏**：上 55% 3D + 下 45% 面板（内部「层级｜审核」切换），纯 CSS | 保持桌面三栏布局（`min-width:1120px` 横向滚动） |
| >900 | 现状不变 | 现状不变 |

通用原则：竖屏只露当前任务控件（结论/添加问题/复位相机），其余进「更多」；移动端只做「看 3D + 记问题」。

## 4. 实施步骤

### Phase 0 地基修复（0.5 天）

- **T0.1 双端根类 + 作用域化**
  - `main-implementation.js` 模板 `.tool-shell` 加 `is-editor`；`reviewer-implementation.js` 模板 `.review-shell` 加 `is-reviewer`（F1 落地）。
  - `shared-ui.css` ≤900 块拆分：**形态规则**（`shell 行模板`/`sidebar fixed 抽屉`/`footer display:none`/`mobile-tabs`/`only-sm` 显隐/`100dvh`/topbar wrap）加 `.is-reviewer` 前缀；**通用触控增强**（按钮 44px、course-rail 压缩、≤400 与高度分支）保持双端。
  - 编辑端新增：`@media (max-width:900px){ .is-editor .tool-shell { min-width:1120px; } }` + `body.is-editor 页面允许横向滚动`（覆盖 `overflow:hidden` 需改在 html/body 层面按类放开，注意仅 ≤900 时）。
- **T0.2** `index.html:3` viewport 补 `viewport-fit=cover`。
- **T0.3** `shared-ui.css:1470,1539` 去掉 toolbar 的 `env(safe-area-inset-bottom)` 叠加（Phase 2 再按 peek 高度重调）。
- **T0.4** `editor/styles.css` `.delete-model` 补 `@media (hover:none)` 常显分支（对齐 `reviewer-implementation.js:265` 做法）。
- **T0.5** `npm run build` + 快速回归（dist 产物探针，见 Phase 5 通道）。
- **验收**：≤900 窄窗编辑端为完整桌面布局可横滚、footer 可见；审核端 ≤900 行为与现状一致。

### Phase 1 审核端 601–900 上下分栏（0.5 天，纯 CSS）

- **T1.1** 断点拆分：现 `@media (max-width:900px)` 中的形态规则迁入 `@media (max-width:600px)`；新增 601–900 档：
  - `.is-reviewer .workspace { grid-template-rows: minmax(0,55fr) minmax(0,45fr); }`（3D 上/面板下），sidebar 回归流内单列（取消 fixed），面板区内部「层级｜审核」用现有 mobile-tabs 思路做行内切换或纵向堆叠（取实测更优者）。
  - 高度分支（≤700/≤500）同步迁移并对 601–900 生效规则复核。
- **T1.2** build + iPad 竖屏视口（768×1024）截图验证。
- **验收**：601–900 无遮挡分栏；≤600 仍为 Phase 0 形态（Sheet 在 Phase 2 落地前暂维持抽屉）。

### Phase 2 审核端 ≤600 Bottom Sheet（1 天 + 2b 0.5 天）

- **T2.1 两态 Sheet**：复用 `.sidebar` DOM（`.is-reviewer` 作用域），状态类 `sheet-peek / sheet-half`；`setMobilePanel` 改造为 `setSheet(name, state)`；peek 高度 48px（`calc(48px + env(safe-area-inset-bottom))`），half 55dvh；tabs 点击 = 切换目标 sheet（同 tab 再点收起）。
- **T2.2 peek 摘要条**：`.sheet-peek` 内常显「模型名 · 结论徽标 · 问题数」，数据源复用 `renderReview` 现有 counts/状态逻辑，渲染时同步更新。
- **T2.3** toolbar bottom 改为 `calc(peek高 + 8px)` 联动（仅 sheet-peek 态；half 态 sheet 覆盖时 toolbar 可被盖住，可接受）。
- **T2.4（2b 可选）拖拽 snap**：peek 条 pointer 拖拽 + 速度方向判定三态（peek/half/full），`transition: transform 220ms var(--ease-out)`；`prefers-reduced-motion` 降级为点按。
- **验收**：iPhone 竖屏看模型同时见摘要条；记问题上滑/点按半屏；外点收起；矮机（≤700 高）half 上限 48dvh。

### Phase 3 编辑端 ≤600 方案 A（1 天）

- **T3.1** 模板补 `mobile-tabs`（「模型」「设置」）+ `only-sm/hide-sm` 文案收纳 + `mobile-more`（版本检测 ⟳ 移入）。
- **T3.2** 抽屉逻辑：`main-implementation.js` 内实现 `setMobilePanel`（约 20 行，与审核端各自实现、注释互指；不抽共享 JS——build-reviewer.mjs 注入机制只覆盖 CSS，避免为 20 行改打包链）。
- **T3.3** ≤600 编辑端 footer 隐藏（脏状态已有 `#save.dirty` 高亮兜底，无信息丢失）；`body` 横滚规则同步收回（编辑端进入移动形态）。
- **验收**：手机可切换浏览课程模型/项目设置；编辑操作引导回 PC（提示条）。

### Phase 4 3D 触摸增强（0.5 天）

- **T4.1** `shared-viewer.js` 初始化处统一：`controls.touches = { ONE: THREE.TOUCH.ROTATE, TWO: THREE.TOUCH.DOLLY_PAN }`，触摸设备降速（`rotateSpeed≈0.5, zoomSpeed≈0.8`，`matchMedia('(pointer:coarse)')` 判定），设 `minDistance/maxDistance`。
- **T4.2** 双击复位相机（`dblclick`，与 OrbitControls 默认无冲突）。
- **T4.3** `visibilitychange` 停/启 rAF 循环。
- **验收**：真机单指旋转/双指缩放平移流畅；双击回正；后台切换不发热。

### Phase 5 回归与部署（0.5 天）

- **T5.1** `npm run build`（`dist/version.json` 随构建更新）。
- **T5.2** Playwright 探针（`--no-proxy-server` + `domcontentloaded`，结果落盘 `tool/output/playwright/`）：≤600/601–900/桌面三档视口，审核端 preview 与编辑端各一轮截图 + 抽屉/sheet 交互断言。
- **T5.3** `upload_dist.py` 部署 → **MD5 复验（不信 exit code）** → 线上 `?v=` 强刷冒烟；E2E 铁律：严禁在云端真实项目上编辑，先 `#draft-new` 建冒烟项目（名含「云同步冒烟-」）。
- **验收**：三档视口截图无回归；线上版本号一致。

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| 900→601 拆分改变桌面窄窗（601–900）行为：审核端从抽屉变分栏 | 分栏对窄窗体验更优，属预期改进；发布说明注明 |
| `generated/reviewer-runtime.js`、`dist` 为产物，源码改动不同步 | 每阶段收尾强制 build + 探针（F8 铁律） |
| 拖拽手势与 3D 手势冲突 | sheet 拖拽仅绑在 peek 条/handle（canvas 之外），无交集 |
| 编辑端 `overflow:hidden` 放开横滚影响桌面 | 仅 `.is-editor` + ≤900 媒体查询内放开 |
| 双击复位与既有交互冲突 | OrbitControls 无双击行为，安全；定位联动（pendingFrame）路径复用现有 `locateNode` 清标志逻辑 |
