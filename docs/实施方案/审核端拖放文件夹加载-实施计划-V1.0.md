# 审核端拖放文件夹加载 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。  
> 背景先读：`docs/apps-code-map.md`、`docs/工具化/README.md`、`docs/实施方案/审核端导出已审HTML-实施计划-V1.0.md`。  
> 决策：P0 只做 **打开 HTML 后拖入审核包解压根目录**；**页内解压 ZIP**、**Directory Picker 记句柄** 入后续阶段，本计划不实现。

## 1. 背景与问题

| 现状 | 说明 |
|---|---|
| 大项目导出 | ZIP 审核包（`审核器.html` + `project.json` + `review/` + `models/`） |
| 审核端打开 | 双击 HTML 后无模型可审，需点顶栏「选择审核包文件夹」 |
| 授权方式 | 仅 `input[webkitdirectory]`，空态弱、易拖错/选错子目录 |
| 硬约束 | `file://` 下 JS **无法**静默读同级目录；必须用户显式授权 |

讨论结论：

1. 审核者最简路径仍是「双击 HTML」；folder 模式做不到零点击，目标是 **一次授权**。
2. 授权入口从「点按钮选目录」升级为 **页面拖放 + 保留按钮回退**，降低找按钮/理解成本。
3. 拖入对象必须是 **含 `project.json` 的解压根目录**，不是单独 `models/`，也不是资源管理器里甩到 html 图标上。

## 2. 目标与非目标

**目标**

1. 审核端在未绑定模型文件时展示明确空态：「将审核包文件夹拖到此处」。
2. 用户把解压根目录拖入页面后，复用既有 `loadDirectory` 完成加载，行为与点按钮一致。
3. 拖入错误（缺 `project.json`、拖了 `models/` 子目录、拖了单文件）给出可行动提示。
4. 顶栏「选择审核包文件夹」保留，作为拖放失败/不习惯拖放的回退。
5. 单 HTML（`mode: 'inline'`）已可审时不阻断；允许拖入新包覆盖当前会话（与重新选文件夹等价）。

**非目标**

- 不实现页内解压 `.zip`（需嵌 JSZip，体积与内存另议）。
- 不实现 `showDirectoryPicker` / IndexedDB 句柄续用。
- 不改导出端 ZIP 结构、`schemaVersion`、`review.byModel`、Issue 字段。
- 不改开发端 `main-implementation.js`。
- 不做本地 HTTP 服务、Electron 壳。

## 3. 设计原则

1. **一次授权、一条加载链路**：拖放展开结果必须进入与 `directory` input 相同的 `loadDirectory(files)`，禁止第二套解析逻辑分叉。
2. **空态可发现**：folder 包打开即见拖放区，而不是等模型加载失败后再猜。
3. **可恢复**：选错/拖错不改变已有可用会话（若已成功加载，则提示失败且不覆盖 `state`）。
4. **文案说人话**：明确「拖入包含 project.json 的解压根目录；不要只拖 models」。

## 4. 技术方案

### 4.1 数据流

```text
开发端 ZIP 导出
  → 审核器.html（嵌 project/review 元数据，mode:'folder'，无 base64Chunks）
  → 用户双击打开
  → 空态：需目录授权才能读 models/*.glb
  → 用户拖入「项目-审核包/」
  → dataTransfer.items → webkitGetAsEntry() → 递归 walk → File[]
  → loadDirectory(files)
       ├─ 找 project.json / review/issues.json
       ├─ state.payload = { project, review, mode:'folder' }
       ├─ state.files = Map(name → File)
       └─ loadModel(首模型)
  → 进入正常审核
```

### 4.2 何时显示拖放空态

| 条件 | 空态 |
|---|---|
| `mode === 'folder'` 且 `!state.files` | **必须显示**（ZIP 包主路径） |
| `mode === 'inline'` 且已有 `base64Chunks` | 不强制；全页仍可接受拖入作为「换包」 |
| 已成功 `loadDirectory` | 收起大空态，顶栏按钮可再次换包 |

判定建议抽成：

```js
function needsFolderFiles() {
  if (!state.payload?.project) return true;
  if (state.payload.mode !== 'folder') return false;
  return !state.files;
}
```

ZIP 导出的 HTML 打开时 `mode:'folder'`、无 `state.files`，满足空态条件。

### 4.3 目录展开（拖放）

```js
async function collectDropFiles(dataTransfer) {
  const files = [];
  const items = [...(dataTransfer.items || [])];
  const entries = items
    .map((item) => (item.kind === 'file' ? item.webkitGetAsEntry?.() : null))
    .filter(Boolean);
  if (!entries.length) {
    // 回退：部分环境只给 FileList（无目录树）
    return [...(dataTransfer.files || [])];
  }
  for (const entry of entries) await walkEntry(entry, '', files);
  return files;
}

function walkEntry(entry, prefix, out) {
  return new Promise((resolve) => {
    if (entry.isFile) {
      entry.file((file) => {
        // 保留相对路径，便于「只拖 models」时诊断；加载仍按 file.name 匹配
        Object.defineProperty(file, 'webkitRelativePath', {
          value: prefix + file.name,
          configurable: true,
        });
        out.push(file);
        resolve();
      }, () => resolve());
      return;
    }
    if (entry.isDirectory) {
      const reader = entry.createReader();
      const readBatch = () => reader.readEntries(async (batch) => {
        if (!batch.length) { resolve(); return; }
        for (const child of batch) await walkEntry(child, `${prefix}${entry.name}/`, out);
        readBatch();
      }, () => resolve());
      readBatch();
      return;
    }
    resolve();
  });
}
```

要点：

- `readEntries` 必须循环读到空数组（浏览器分批返回）。
- 不强制 `webkitRelativePath` 与 `loadDirectory` 的 `file.name` 匹配逻辑（现有 Map 按 `name`）；P0 不改匹配规则，见 §6 风险。
- 若拖入多根（多个文件夹/文件混拖），全部展开后一并交给 `loadDirectory`。

### 4.4 与 `loadDirectory` 衔接

复用现有函数，仅在入口增加校验提示分支（不改业务解析）：

```js
function loadDirectory(files) {
  const projectFile = [...files].find((f) => f.name === 'project.json');
  if (!projectFile) {
    const hasGlb = [...files].some((f) => /\.glb$/i.test(f.name));
    $('status').textContent = hasGlb
      ? '未找到 project.json：请拖入审核包解压根目录（含 project.json 与 models），不要只拖 models'
      : '请选择/拖入审核包解压根目录';
    return;
  }
  // ... 原有解析逻辑不变
}
```

加载失败（JSON 坏、缺 models）时：**已成功过一次**则不覆盖 `state.payload` / `state.files`。实现方式：先解析到局部变量，成功后再赋值（当前实现已是先 parse 再赋值，保持；补 catch 不写坏状态）。

### 4.5 拖放 UI

**空态层（主视觉）**

- 位置：覆盖 `section.stage`（中央画布），`position:absolute; inset:0`，不影响左右侧栏已有结构。
- 内容：
  - 标题：将审核包文件夹拖到此处
  - 说明：解压 ZIP 后，拖入包含 `project.json` 的整个文件夹
  - 次要操作：或点击「选择审核包文件夹」（触发既有 `#directory`）
- 状态：
  - 默认：半透明底 + 虚线边框
  - `dragover`：高亮强调（accent 描边/底色）
  - 加载中：可禁用 drop，防重复进入

**全页热区（增强）**

- 对 `window`/`document` 做 `dragover`/`drop` 的 `preventDefault`，避免浏览器直接打开 glb 丢上下文。
- 主 drop 处理绑定在空态层；`needsFolderFiles()` 为 false 时也允许在空态隐藏后，对 `stage` 拖入换包（顶栏按钮已支持）。

**保留入口**

- 顶栏「选择审核包文件夹」文案与行为不变。

### 4.6 样式归属

- 空态层样式优先写入审核端注入 CSS（`reviewer-implementation.js` 内既有 style 块），类名建议 `.folder-drop-overlay`、`.folder-drop-card`。
- 不改 `shared-ui.css`（避免开发端无谓变化）；若需复用空态间距，可少量引用已有 token 变量。
- 主题：跟随 `document.documentElement.dataset.theme` 亮/暗。

### 4.7 单 HTML 会话

- `mode:'inline'` 启动即审，不显示阻挡型空态。
- 仍接受拖入：等同换包，成功则替换 `state.payload` / `state.files` / 模型缓存；失败提示且不破坏当前模型。

## 6. 边界与风险

| 风险 | 处理 |
|---|---|
| Safari 对 `webkitGetAsEntry` 支持弱 | 按钮 `webkitdirectory` 回退必须保留；检测无 entries 时回退 `FileList` |
| 用户拖入 `models/` | 无 `project.json` → 明确提示上一级 |
| 同名 GLB 跨目录 | P0 仍按 `file.name` Map；冲突沿用现状（后写覆盖）。不在本计划改路径匹配 |
| 超大目录拖入卡顿 | walk 异步进行；空态显示「加载中」；失败可重试 |
| `file://` 下部分浏览器限制 Directory API | 产品以 Chromium 为主要验收环境；按钮路径兜底 |
| 已审导出 | folder 模式本就禁用「导出已审 HTML」；本计划不改变该规则 |

## 7. 阶段划分

### P0 拖放文件夹（本计划必做）

1. `needsFolderFiles()` + stage 空态层（含 dragover 高亮）。
2. `collectDropFiles` / `walkEntry` + 全页 `preventDefault`。
3. 接入 `loadDirectory`；失败文案与「不覆盖已有成功状态」。
4. 顶栏按钮保留；空态内可点击触发同一 input。
5. 亮/暗主题下样式可用。

### P1（本计划不实现，仅预留）

- 页内解压拖入的 `.zip`。
- `showDirectoryPicker` + IndexedDB 权限续用。
- 按 `webkitRelativePath` 的精确子目录匹配。

- [ ] 开发端导出 ZIP → 解压 → 双击 `审核器.html` → 出现拖放空态。

- [ ] 只拖 `models/`：提示含 `project.json` 的根目录，不进入半初始化状态。

- [ ] `npm run build`（或项目既有构建命令）通过；导出单 HTML 冒烟不回归。
