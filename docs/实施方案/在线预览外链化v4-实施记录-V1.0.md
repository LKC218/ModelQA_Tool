# 在线预览外链化 v4 - 实施记录 V1.0

> 2026-09-14 定案并上线（v1.2.5）。前序讨论见当日会话记录；服务端接口契约同步本文 §2。

## 1. 背景与定案

- 现象：数字电路项目审核包 29.62MB，「单 HTML / 生成在线预览」按钮被禁（提示走 ZIP）。
- 定位：20MB 闸门是**纯客户端常量** `LIMIT = 20*1024*1024`（main-implementation.js:14）；服务端 nginx `client_max_body_size 200m`、Python `MAX_BODY = 200MB`，链路本就通畅。
- 决策（用户排除应急、一次到位）：在线预览放弃自包含内嵌，改**外链资源化（payload v4）**；「单 HTML / ZIP」保留 v3 自包含语义与 20MB 闸门（管本地分发）。
- 回传冲突性复查结论：不冲突且受益。现有回传链 `POST /api/reviews/submit` 生成新短 ID（不覆盖原链接），v4 下回传 HTML 内嵌 runtime+结论、模型走外链索引 → 回传体积 20MB 级降到几百 KB；assets sha256 内容寻址 + 不删除 → 无版本漂移。

## 2. v4 契约

### payload（编辑端生成）

```jsonc
{
  "schemaVersion": 4,
  "mode": "external",
  "submitToken": "...",
  "modelData": [ { "key": "<sha256>", "fileRef": "<base>-<hash8>.glb", "size": 12345, "url": "https://3d.propanda.cn/reviews/assets/<sha256>.glb" } ],
  "project": { "models": [ { "...": "...", "dataKey": "<sha256>", "fileRef": "..." } ] },
  "review": { "...": "..." }
}
```

- v3（inline，modelData 带 base64Chunks）与 v2（models 自带 base64Chunks）语义不变，审核端三态兼容。
- `mode: 'external'` 贯穿回传产物：`buildReviewedPayload` 对 v4 透传外链索引并保持 mode=external。

### 服务端新接口

- `POST /api/upload-asset`（全权 Token）：body 为 GLB 二进制，头 `X-Asset-SHA256: <64hex>`；服务端校验 sha256(body) 与头一致 → 落盘 `/var/www/modelqa-data/reviews/assets/<sha256>.glb`（tmp + os.replace 原子写 + 0644）；已存在直接 `dedup: true`（幂等，支持断点重试）。响应 `{hash, url, dedup}`。
- sha 不一致 / 头缺失 → 400；空 body（无 Content-Length）→ 400（read_body 既有行为，空 asset 属无效输入）。
- **静态直出由 nginx 承担**（不经 Python）：`location /reviews/assets/` alias + `Cache-Control: public, max-age=31536000, immutable` + `Access-Control-Allow-Origin: *`。CORS 头使下载到本地 `file://` 打开的外链 HTML 联网时也能加载模型。
- assets 不随 review 删除（内容寻址、多预览共享）；`/reviews/assets/` 无 autoindex，不可枚举。

### 编辑端上传流程（uploadOnlinePreview 重写）

1. `buildContentIndex()` → pool（sha256 key，与云端模型库一致）
2. `payloadExternal()` 构建占位 payload（url 空）
3. 逐个 `POST /api/upload-asset`（按钮进度「上传模型 i/n…」，toast 同步），url 回填
4. 全部成功 → `reviewerHtml(data)`（几百 KB）→ `POST /api/upload` → toast 返回短 ID 链接
5. key 非 64hex（非 HTTPS 环境 crypto.subtle 不可用兜底）→ 明确报错提示
6. `updatePackage()`：「生成在线预览」只看 `!total`；>20MB 时 status 提示「可导出 ZIP 或生成在线预览（单 HTML 不可用）」

### 审核端消费（reviewer-implementation.js）

- `assetUrl(model)`：schemaVersion>=4 且 mode=external 时按 dataKey 从池取绝对 http(s) url
- `loadModel` buffer 链：inlineChunks(v2/v3) → state.files(folder) → **fetchAssetBuffer(v4 新增)** → throw
- `collectModelBinaries`（已审 ZIP）同样加 fetch 分支；`canExportReviewedHtml/Zip` 对 external 特判（every(assetUrl)）
- `buildReviewedPayload`：`mode: schemaVersion>=4 ? 'external' : 'inline'`

## 5. 部署坑与修复

1. **inject_into_servers 块跳过 bug**：内层收集 server 块退出后外层又 `i += 1`，紧邻的下一个 `server {` 行被跳过 → 注入后括号错乱、nginx -t 失败（`listen not allowed`），脚本自动回滚。P0 时代靠块间空行侥幸通过。修复为「每轮消费一个完整块或单行」结构，本地模拟（sim_patch_nginx.py + 备份 conf）验证 2 块注入、depth=0 后再上线。
2. **autoindex 冒烟过时**：短 ID 机制后落盘名为短 ID，grep 'smoke' 永远 FAIL（存量问题，与本次无关）。修复为按上传返回的文件名检索。
3. **prod 冒烟 DELETE 路径**：DELETE 必须走 `/api/reviews/<name>`（代理到 Python），静态 `/reviews/<file>` 返回 405。
4. **幂等断言**：冒烟脚本重复运行时确定性内容会 dedup=true，冒烟内容需随机化（os.urandom 前缀）。

## 6. 遗留与后续可选项

- assets 上传为逐文件 fetch，无单文件内进度（多文件计数进度已有）；如需单文件进度可复用审核端 XHR 模式
- Draco/meshopt 压缩 assets 为可选增强（sha256 会变，key 生成处统一处理即可）
- 多审核员并发回传 = 多份「-已审」并存（现状既有语义），如出现真实协作需求再做轻量提示
