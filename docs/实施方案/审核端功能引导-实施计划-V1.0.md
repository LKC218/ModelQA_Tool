# 审核端功能引导 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。  
> 背景先读：`docs/apps-code-map.md`、`docs/工具化/README.md`、`docs/实施方案/审核端拖放文件夹加载-实施计划-V1.0.md`、`docs/实施方案/审核端导出已审ZIP-实施计划-V1.0.md`。  
> 决策：P0 做 **首次聚光灯导览 7 步（A 方案）+ 跳过/完成 + localStorage + 「?」重播**；完整「?」说明抽屉、空态入口、迷你示意图入 P1；**不引入 Intro.js/Driver.js CDN**。

## 1. 背景与问题

| 现状 | 说明 |
|---|---|
| 审核端能力 | 拖放/选择审核包、课程条、层级树、零件 Issue、三态结论、导出已审 ZIP/HTML/JSON |
| 首次体验 | 仅有拖放空态长文与局部 placeholder，缺任务流引导 |
| 用户 | 第一次使用的审核者，需快速了解「在哪里点、做什么」 |
| 硬约束 | 离线单 HTML/ZIP、零外部资源、不破坏既有审核与导出契约 |

讨论结论：

1. 引导应做成 **任务流**，不是功能说明书；主线只保留「拖包 → 选模型 → 标问题 → 定结论 → 导出 ZIP」。
2. 形态采用 **聚光灯导览**（对标 Driver.js/Intro.js/Slack 首启），自研轻量实现以满足离线。
3. 视觉在基础挖洞上升级：**毛玻璃遮罩 + 细描边 + 步切换轻脉冲**，浮层小卡片，避免全屏 Welcome。
4. 文案采用 **V0.3 / A 方案 7 步**（见第 7 节与 §5.2），最后一步主推「导出已审 ZIP」；第 4 步突出快捷键 **G**。
5. 空态拖放与导览不叠两层长文；功能细节进顶栏「?」。

## 2. 目标与非目标

**目标**

1. 每次打开审核端（页面重新加载）均自动进入导览，7 步可走通，可跳过、可完成。
2. 完成/跳过仅关闭本轮，不阻止下次自动弹出；顶栏「?」可「重新播放引导」。
3. 高亮锚定真实 UI 区域，文案与 V0.2 上屏稿一致（主推导出已审 ZIP）。
4. 单 HTML 与 ZIP 解压打开（inline / folder）均能出导览。
5. 零外部依赖；导览随审核 runtime 打进离线包。

**非目标**

- 不做滚动叙事、多页全屏 Welcome、重插画/粒子动效。
- 不引入 Intro.js、Driver.js 等 CDN/外网资源。
- 不改 `schemaVersion`、`review.byModel`、Issue 字段、开发端导出逻辑。
- 不实现页内解压 ZIP、Directory Picker 句柄续用。
- P0 不做迷你 UI 示意图与完整「?」分区抽屉（见 P1）。

## 3. 设计原则

1. **任务优先**：每步「要做什么 + 在哪里点」，正文 ≤ 2 行；细节进「?」。
2. **真实锚点**：高亮现有 DOM（id/类），目标缺失则跳步，不卡死。
3. **可跳过、可重播**：ESC/跳过即关；完成后可从「?」重播。
4. **视觉不抢戏**：毛玻璃仅弱化外围；描边与主题 primary/结论色协调；pulse 每步 1 次。
5. **与空态协同**：导览第 1 步优先；空态不重复长文（P0 可保留现有空态，导览覆盖时以导览为准）。

## 4. 形态选型（已否决项）

| 模式 | 结论 |
|---|---|
| 聚光灯导览（自研） | **采用** |
| 任务清单 checklist | 不单独作主线；可 P1 进「?」 |
| 热点小气泡 | P2 可选，补充快捷键 |
| 全屏 Welcome 多页 | 否决 |
| 滚动叙事 | 否决 |
| 引 Driver.js 全量库 | 否决（体积/离线/样式贴合度） |

## 5. 交互与视觉规格

### 5.1 导览容器

- 全屏 `fixed` 根层 `pointer-events: none`；**不用**整页 `backdrop-filter` 蒙层（会模糊并挡住高亮区）。
- **四边遮罩挖洞**：上/下/左/右四块 `.onb-panel` 做半透明 + blur，中间留出真实洞；洞内可直接点击拖放/按钮。
- 高亮描边：`.onb-ring` 细描边，`pointer-events: none`；步切换 pulse 1 次。
- 浮层：宽约 340px；结构 = 角标 + 标题 + 一句正文 + 按钮区。
- 顶部细进度线（5 段或单条进度）。
- 动效：目标/浮层约 240ms ease；步骤切换目标框 pulse 1 次（约 600ms）。
- 浏览器不支持 blur 时降级：半透明底 + 普通描边。

### 5.2 步骤与 target（现行 V1.2 · 9 步极简）

| 步 | 上屏标题 | body（一句动作） | tip | target | 主按钮 | 门禁 |
|---|---|---|---|---|---|---|
| 1 | 拖入审核包 | 把审核包文件夹拖到这里 | 含 project.json，不要只拖 models | `.folder-drop-card` / `#folder` | 下一步 | **须先加载包**；waiting=「先拖入审核包」 |
| 2 | 选课程 | 点顶部卡片，选要审的课程 | 卡片上的 0/4 是进度 | `#review-course-cards` / `.course-rail` | 下一步 | — |
| 3 | 选模型 | 在左栏点模型，切换审核对象 | 黄点 = 未结论 | `.course-model-panel` / `#review-models` | 下一步 | — |
| 4 | 模型层级 | 单击零件，选中要看的部位 | 可搜索零件名 | tree 所在 `.panel` | 下一步 | — |
| 5 | 只看这个零件 | 双击零件，淡化其他 | 再双击、G 或 ESC 退出 | 同 tree 面板 | 下一步 | — |
| 6 | 看视口 | 拖拽旋转，滚轮缩放 | 「还原」回默认视角 | `.viewer-toolbar` | 下一步 | — |
| 7 | 记问题 | 标状态，写一句问题 | 绑定当前零件更好定位 | 问题记录 panel | 下一步 | — |
| 8 | 定结论 | 选通过 / 待改 / 阻断 | 可补一句说明 | `#model-status` 所在 panel | 下一步 | — |
| 9 | 导出 ZIP | 点「导出已审 ZIP」交回开发方 | （空） | `#export-zip` | 完成 | — |

规则：

- 目标 `display:none` / 不存在 → 居中卡片说明（不自动跳步）。
- `resize` / 布局变化 → 重算高亮矩形。
- 第 1 步就绪判定：`#folder-drop` 已 `hidden`（inline 已有包或 folder 已授权加载）。
- **每次启动均自动弹出**；完成/跳过仅关闭本轮。
- `prefers-reduced-motion: reduce` 关闭 pulse 与卡片入场动画。
- 记忆 key：`an_reviewer_onboarding_v2`（7 步文案升级后强制重播一次）。

### 5.3 浮层按钮

| 按钮 | 行为 |
|---|---|
| 主按钮（下一步/完成） | 中段步骤主按钮文案为「下一步」，第 7 步为「完成」；门禁未过则禁用；完成写记忆 |
| 上一步 | 有历史时显示（第 1 步隐藏） |
| 跳过 / ESC | 关闭导览；**跳过不写 done，完成才写 done** |

### 5.4 触发与记忆

| 场景 | 行为 |
|---|---|
| 首次无 `an_reviewer_onboarding_v2` | 启动后自动第 1 步 |
| 已 `done` | 不自动弹 |
| 「?」→ 重新播放引导 | 从第 1 步强制打开 |
| localStorage 不可用 | 仅本次会话内存标记，不阻断审核 |

- key：`an_reviewer_onboarding_v2`
- 值：`done`（P0 最小）；可选扩展 `skipped` / `{step}`（P1 续播，默认不做）

### 5.5 「?」菜单

**P0（最小）**

- 顶栏增加「?」或复用现有帮助入口。
- 菜单项：重新播放引导。

**P1（说明抽屉）**

- 右侧抽屉或轻量弹层，复用 shared panel 样式。
- 条目：界面分区 / 快捷操作（G、适配、线框）/ 结论三态含义 / 打不开模型 / 结果怎么交（优先导出已审 ZIP）。

### 5.6 与空态关系

| 条件 | 导览第 1 步 | 空态卡 |
|---|---|---|
| folder 未加载且导览进行中 | 高亮拖放区 | 可保留 DOM，视觉以导览遮罩为主 |
| 导览关闭后仍无包 | — | 沿用现有拖放空态 |
| P1 | — | 可加短句「第一次用？看 1 分钟引导」 |

## 6. 技术方案

### 6.1 模块划分

| 层 | 位置 | 职责 |
|---|---|---|
| 步骤配置 | `ONBOARDING_STEPS` 常量（onboarding 模块内） | title、body、target、primaryLabel |
| 导览运行时 | **新建** `tool/src/reviewer/reviewer-onboarding.js` | 启停、步进、高亮计算、记忆、ESC |
| 入口接线 | `tool/src/reviewer/reviewer-implementation.js` | 启动判定开导览；「?」重播绑定 |
| 样式 | 审核端注入 CSS 或 onboarding 内 style | 类名前缀 `onb-`；颜色用 shared CSS 变量 |
| 构建 | `tool/scripts/build/build-reviewer.mjs` | 将 onboarding 打进审核 runtime / 已审 HTML 壳 |

### 6.2 导出的最小 API（建议）

```js
// reviewer-onboarding.js
export function initReviewerOnboarding(options) {
  // options: { shouldAutoStart?, getTargets?, storageKey?, onDone?, onClose? }
  return { start, startFrom, destroy, isOpen };
}
```

`reviewer-implementation.js` 在 UI 挂载后调用 `initReviewerOnboarding`，并在「?」菜单触发 `start()`。

### 6.3 高亮计算

1. `document.querySelector(target)` → `getBoundingClientRect()`。
2. 计算 page 偏移（含 scroll）→ 更新挖洞 `box-shadow` 与描边元素位置。
3. `ResizeObserver` 或 `resize` + 步进时重算。
4. 浮层定位：优先目标下方/侧方，越界则翻转；始终保证在 viewport 内。

### 6.4 构建与离线

- onboarding **不得** `import` 外网或仅 dev 依赖包。
- 确认 esbuild 打包 `reviewer-entry` → `reviewer-implementation` → `reviewer-onboarding` 链路完整。
- 导出「已审 HTML / 已审 ZIP」后，双击打开仍能出首次引导（同一 runtime）。

### 6.5 无障碍与输入

- ESC：跳过并关闭。
- 不强制焦点陷阱到浮层，避免与 3D 视口/树快捷键冲突；P1 可加 `aria-modal="true"` 与简单 Tab 环。
- 遮罩 `pointer-events`：空白处点击可选择「跳过」或忽略（默认忽略，不误关）。

## 7. 文案（V0.2 上屏稿）

> 完整讨论稿见会话沉淀；实现以本节精简上屏文案为准。

### 7.1 开场卡（可选，P0 可省略直接进步骤 1）

- 标题：第一次用？1 分钟走完审核流程  
- 正文：按 5 步做一遍即可完成一个模型的审核。随时可跳过，之后点「?」再看。  
- 主按钮：开始引导　次按钮：跳过  

### 7.2 步骤 1 · 拖入审核包

- 目标：先让工具拿到要审的内容。  
- 操作：把解压后的审核包文件夹拖到中间；或点「选择审核包文件夹」。要拖整个包（含 `project.json` 和 `models`），不要只拖 `models`。  

### 7.3 步骤 2 · 选课程与模型

- 目标：一次只审一个模型，先选中它。  
- 操作：点顶部课程卡片选课程；再点「模型 N」或左侧模型名。  
- 提示：卡片 `已审核/总数` 随进度更新。  

### 7.4 步骤 3 · 看模型、标问题

- 目标：在 3D 里找到问题零件，记下问题。  
- 操作：视口旋转缩放；左侧层级或视口单击选零件；右侧「问题记录」填写，状态选 通过 / 待改 / 阻断。  
- 小技巧：淡化其他 / 适配 / 线框。  

### 7.5 步骤 4 · 给模型下结论

- 目标：一个模型只保留一个最终结论。  
- 操作：右栏「模型结论」看审核要求；选 通过 / 待改 / 阻断；必要时写说明。  
- 提示：零件问题记「问题记录」，模型结论记「模型结论」，两层不要混。  

### 7.6 步骤 5 · 导出已审 ZIP

- 目标：把审核结果打包交回开发方。  
- 操作：确认顶栏进度；点主按钮「导出已审 ZIP」；ZIP 发给开发方，解压后打开 `审核器.html`。  
- 次级：导出已审 HTML / JSON。  
- 边界：ZIP 解压包（folder）若 HTML 禁用，仍优先「导出已审 ZIP」。  

### 7.7 「?」说明（P1）

| 条目 | 一句话 |
|---|---|
| 界面分区 | 顶栏进度与导出；上排选课；左树选零件；中间看模型；右栏写结论与问题 |
| 快捷操作 | G 淡化其他；适配；线框 |
| 结论含义 | 通过=可交付；待改=需修改但不挡进度；阻断=必须先改 |
| 打不开模型 | 拖入整个审核包根目录，不是单 glb / models 子文件夹 |
| 结果怎么交 | 优先「导出已审 ZIP」 |

## 9. 验收清单（P0）

1. 清除 `an_reviewer_onboarding_v2` 后打开审核端 → 自动出现第 1 步。  
2. 7 步均可「主按钮」前进；可「跳过」关闭；第 7 步「完成」写入 `done`。  
3. `done` 后刷新不再自动弹；「?」→「重新播放引导」可从第 1 步打开。  
4. 高亮大致对齐：拖放区、课程条、问题记录、模型结论、导出 ZIP。  
5. 1440×900 与 1280×800 下浮层不溢出、高亮不错位；resize 后可重算。  
6. 单 HTML（inline）与 ZIP 解压 folder 模式均可出导览。  
7. 导出已审 ZIP / HTML / JSON 行为与导出前一致；无外网请求。  
8. ESC 可关闭；关闭后拖放/树/结论/导出仍可用。  

**P1 补充**：说明抽屉内容正确；空态入口可打开导览。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 挖洞 + blur 兼容性 | blur 失败降级半透明；固定测试 Chrome/Edge |
| 第 3 步双区域复杂 | P0 单区域问题记录 |
| target 在导览时尚未渲染 | 启动延后到 `requestAnimationFrame`/UI 挂载后；失败跳步 |
| 与 confirm/拖放叠加 | 导览不拦截业务；业务弹窗优先 |
| 文案过长挤浮层 | 每步正文 ≤ 2 行；按钮文案固定短词 |
| 打进离线包失败 | T6 显式验证已审 HTML 内导览存在 |
