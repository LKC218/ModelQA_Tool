# 定位爆炸视图实施计划

> 版本：V1.0 ｜ 日期：2026-09-12 ｜ 状态：已实施并验证上线（E2E 14/14 PASS，MD5 校验一致）

## 1. 背景与目标

爆炸视图（见《爆炸视图与部件标注功能实施方案》）与 Issue 定位（`locateIssue` → 描边选中）此前各自独立。审核中大量 Issue 出在装配体内部零件（发电机定子、电机绕组等），目标被外壳遮挡时描边不可见，定位形同虚设。

本功能将两者打通：**定位 Issue 时若目标零件被遮挡，自动爆炸露出 + 相机取景到目标零件**。

已确认的两个关键取舍：
- **仅遮挡时触发**（raycast 检测），可见零件保持现状不扰动视角；
- **触发爆炸后自动取景**（相机平滑推近目标）。

## 2. 技术设计

### 2.1 遮挡检测 `isNodeOccluded(node)`

- 相机 → 目标包围盒 4 个采样点（中心、顶面中心、两个对侧棱面中心）做 raycast；
- 采样射线 `far = 距离 - 尺寸 5% 余量`，只关心到达目标表面前的遮挡；
- ≥2 个采样点命中无关几何即判遮挡（宁漏不误，避免对可见零件误爆炸）；
- 隔离态的幽灵材质 mesh（`ghostOwners`）视为可透视，不计入遮挡。

### 2.2 相机取景 `frameNode(node)`

- 保持当前视线方向，仅按目标包围盒半径（×0.7，距离 ×1.7 留白）拉近、视点落到目标中心；
- 指数趋近动画（每帧 lerp 0.16，阈值 2% 半径），无瞬跳、不打断用户视角感。

### 2.3 组合入口 `locateNode(node)`

| 条件 | 行为 |
|---|---|
| 可炸 && 爆炸系数 < 1 && 目标被遮挡 | `setExplode(1)` 平滑爆炸，动画到位后自动取景，返回 `{ exploded: true }` |
| 其余（目标可见 / 已处于爆炸态 / 不可炸） | 立即取景，爆炸态不动，返回 `{ exploded: false }` |

- **不做自动收拢**：设计期曾考虑「定位到可见零件时收拢定位自动开的爆炸」，但收拢会让「仅在爆炸后才可见」的零件重新被挡，取景到的是藏住的零件。按 KISS 砍掉，爆炸态由用户手动关闭或切模型复位，行为可预期。
- 取景延迟机制：遮挡触发时挂起 `pendingFrame`，`tickExplode` 检测到爆炸动画到位（`explodeFactor === explodeTarget`）后再执行 `frameNode`，避免取景到移动中的目标。
- 内部 `setExplode` 后通过 `notifyExplodeChanged()`（`reason: 'explode-changed'`）广播事件，双端 toolbar 经 `bindViewportTools` 的 `onViewState` 订阅自动同步按钮/滑块态。

## 3. 改动清单

| 文件 | 改动 |
|---|---|
| `tool/src/shared/shared-viewer.js` | 新增 `isNodeOccluded / frameNode / tickFrame / locateNode / settleFrameAfterExplode / notifyExplodeChanged`；`tickExplode` 动画到位回调；`watchModelRoot` 切模型清空 `pendingFrame / frameGoal`；animate 循环挂入 `tickFrame`；API 暴露 `locateNode / isNodeOccluded` |
| `tool/src/reviewer/reviewer-implementation.js` | `locateIssue()` 命中目标后调用 `viewer.locateNode(target)`；自动爆炸时状态条提示「目标零件被遮挡，已自动爆炸露出」 |
| `tool/src/generated/reviewer-runtime.js` | 构建产物（`npm run build` 内含 `prepare:reviewer` 自动重生成） |

**范围决策**：编辑端不接入。编辑端无 Issue 列表定位流程，`selectNode` 由零件树点击 / 视口拾取驱动，树上点选即自动爆炸会违反用户预期。若后续编辑端需要，可为零件树增加显式「定位」按钮再接 `locateNode`。

## 4. 测试方案

1. `npm run build` 通过，`dist/index.html` 含新 API（已验证）；
2. 加载发电机 GLB，登记一个内部零件（如定子）Issue → 点击定位：应自动爆炸 + 相机推近 + 描边 + 状态条提示；
3. 登记外壳表面零件 Issue → 定位：不爆炸、仅描边；
4. 自动爆炸后手动拖滑块 / 点爆炸按钮：行为正常，切模型后爆炸自动复位；
5. 单 mesh 模型（电容）：定位只描边（不可炸路径）；
6. 隔离态下定位：幽灵 mesh 不误判为遮挡。

**实测结果（2026-09-12，reviewer-preview 样例页 + playwright E2E，探针 `scripts/smoke/probes/probe-locate-explode.cjs`）**：14/14 PASS，零 pageerror。
- 可见零件定位：不爆炸、相机取景偏差 0.002；
- 遮挡零件定位：`isNodeOccluded=true` → 自动爆炸 `factor=1` → 动画到位后取景偏差 0.002（取景目标跟随爆炸后的新位置）；
- 工具栏爆炸按钮/滑块经 `explode-changed` 事件同步激活；
- `locateIssue` UI 全链路（树选零件 → 登记 Issue → 点击定位）：状态条提示 ✓、爆炸 ✓、选中 ✓。
- 实施中发现并修复 2 个真实 bug：① `locateNode` 引用了闭包中不存在的 `isExplodable()`（ReferenceError），改为直接判 `explodeParts.length`；② `tickFrame()` 未挂入 animate 循环（编辑未落盘），相机取景因此不生效。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 薄壁 / 镂空模型遮挡误判 | 4 采样点 + ≥2 判定阈值，宁漏不误 |
| 爆炸后目标仍被同单元外壳包住 | V1 接受（相机已取景+描边）；实测高频再迭代 V2（单元内二次爆炸或自动 isolate） |
| 相机取景打断用户视角 | 仅遮挡触发路径取景；保持视线方向只拉近，无环绕突变 |
| 定位时目标正在移动（爆炸动画中） | `pendingFrame` 延迟到动画到位后取景 |
