# 在线预览链接管理与删除 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。
> 背景先读：`docs/apps-code-map.md`、`docs/实施方案/开发端云端持久化与审核包在线托管-实施计划-V1.0.md`。
> 服务端代码不在本仓库：`G:\项目\服务器部署\modelqa-data-server.py`（单文件、Python 3 标准库），部署脚本 `deploy_data_service_update.py`。

## 1. 背景与讨论结论

| 讨论点 | 结论 |
|---|---|
| 链接如何管理 | 以服务端 `/api/reviews` 列表为唯一数据源，开发端出管理面板（打开/复制/删除），不在 localStorage 另记一份 |
| 链接名称过长 | 文件名短码化（课程码-日期），页面 `<title>` 保留课程全称；建立课程码对照表 |
| 能否删除 | 能。删除必须走服务端接口（`/reviews/` 是静态文件，前端删不掉）；已发链接删除后立即失效，删除需二次确认；先做软删除（移入 `_archive/`）可恢复 |

## 2. 目标与非目标

**目标**

1. 服务端新增 `GET /api/reviews/list`（列表：文件名、大小、上传时间、URL）与 `DELETE /api/reviews/<name>`（软删除，移入 `reviews/_archive/`）。
2. 开发端新增「在线预览链接」管理面板：列表 + 打开 / 复制 / 删除（二次确认）。
3. 审核包文件名短码化：`<课程码>-<MMDD-HHmm>.html`，课程码对照表配置化；页面标题保留课程全称。

**非目标**

- 不做硬删除、不做回收站 UI（归档目录手动清理即可）。
- 不做账号/权限（沿用固定 Token `X-ModelQA-Token`）。
- 不改审核端运行时与导出格式（schemaVersion / JSON 契约不变）。

## 3. 服务端改动（P0，`G:\项目\服务器部署\modelqa-data-server.py`）

沿用现有 handler 结构（`do_GET` / `do_DELETE` 已存在，照 `delete_project` 同款写法）：

| 方法 | 路径 | 响应 | 说明 |
|---|---|---|---|
| GET | `/api/reviews/list` | `{ reviews: [{name, size, uploadedAt, url}] }` | 扫 `REVIEWS_DIR` 顶层 `*.html`，mtime 作 uploadedAt |
| DELETE | `/api/reviews/<name>` | `{ ok: true }` | **软删除**：`os.rename` 到 `reviews/_archive/<name>`；name 需严格校验（仅 `[\w\-]+\.html`，防目录穿越，仅允许顶层，禁 `_archive` 本身） |

部署：改完先本地冒烟（参考 `_archive/local_smoke_data_server.py`），再跑 `deploy_data_service_update.py`，服务器侧留时间戳备份（既有惯例）。

## 4. 开发端改动（P1，本仓库）

### 4.1 `tool/src/editor/cloud-sync.js`

新增两个方法（唯一 fetch 出口，与 `deleteProject` 同款）：

```js
listReviews()               // GET /api/reviews/list
deleteReview(name)          // DELETE /api/reviews/<encodeURIComponent(name)>
```

本地 dev 无需改 Vite proxy（`/api` 已转发生产站点）。

### 4.2 `tool/src/editor/main-implementation.js`

- 新增「在线预览链接」面板入口（与现有导出/上传按钮同区域）：
  - 打开面板时拉 `listReviews()`，按上传时间倒序；
  - 每条：文件名 / 时间 / 大小 + 「打开」「复制」「删除」；
  - 删除：`confirm` 二次确认（文案明示「链接将立即失效」）→ `deleteReview` → 刷新列表；
  - 云端不可用（Token 未配置 / 请求失败）时禁用入口并提示，与现有上传按钮行为一致。
- 上传成功后不写本地记录，面板数据一律以服务端为准。

### 4.3 文件名短码化（P2，可随 P1 一起或后置）

- `state.project` 增加课程码字段（或本地配置文件维护「课程全称 ↔ 短码」对照表）；
- 导出/上传文件名模板：`${safeName(课程码)}-${MMDD}-${HHmm}`；
- `reviewerHtml()` 的 `<title>` 保持课程全称：`${project.name} · 审核报告 ${日期}`；
- 历史长名文件不强改，新上传走新命名。

## 6. 风险与提示

1. **删除即失效**：已发给审核员的链接删除后立即 404，面板删除必须二次确认。
2. **路径安全**：DELETE 的 name 必须白名单校验，杜绝 `../` 目录穿越。
3. **归档膨胀**：`_archive/` 不对外暴露（Nginx 仅静态直出 `/reviews/` 顶层 html；如 autoindex 会列目录，需在 Nginx 排除 `_archive`）。
4. **回滚**：服务端改动前按惯例做时间戳备份，可整体回退。
