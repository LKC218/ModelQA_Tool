# 开发端云端持久化与审核包在线托管 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。
> 背景先读：`docs/apps-code-map.md`、`docs/工具化/README.md`、`docs/实施方案/多模型审核工具化实施计划-V1.0.md`。
> 运维侧上下文：部署脚本与服务器凭据在 `G:\项目\服务器部署\`（已被 gitignore 排除），服务器为 Ubuntu 22.04 + Nginx（443 SNI 分流，站点在回环 8444），站点根 `/var/www/model-review-tool/`，访问地址 `https://3d.propanda.cn`。
> 已拍板：后端用 **Python 3 标准库**（零依赖，服务器自带，运维脚本本就是 .py 体系）；鉴权用 **固定 Token 请求头**；数据策略 **本地优先双写 + 防抖同步云端**。

## 1. 背景与问题

| 现状 | 说明 |
|---|---|
| 开发端数据 | 课程/审核要求/多槽草稿全部存浏览器 localStorage（上限 10 条），GLB 以 base64 内嵌 |
| 致命缺陷 | 换设备、清缓存、浏览器数据丢失 = 项目全丢；localStorage 5MB 配额限制大模型 |
| 审核包分发 | 开发端导出单 HTML 后需手动传给审核员，无在线预览入口 |
| 服务器 | 已托管开发端 dist 静态站点（`https://3d.propanda.cn`），无任何后端 API |

讨论结论（已与开发者确认）：

1. 「草稿」升级为「云端长期项目」：数据与 GLB 模型同步到服务器，任何设备打开站点即恢复。
2. 审核包导出后**一键上传**服务器，自动生成在线预览链接（审核员浏览器直接打开审核）。
3. 两者共用**同一个极简后端资源服务**，一次部署，前端两功能并行开发。

## 2. 目标与非目标

**目标**

1. 服务器提供资源服务（`/api/projects`、`/api/models`、`/api/upload`），systemd 守护，Nginx 反代，外网仍只开 22/443。
2. 开发端「草稿列表」升级为「云端项目列表」：项目 JSON 存服务器，GLB 按 hash 上传去重、草稿只存引用。
3. 本地优先双写：保存先写 localStorage（离线可用），防抖后同步云端；服务器不可达不中断编辑，恢复后补同步。
4. 旧 localStorage 草稿**首次启动自动迁移**：模型上传服务器 → 项目记录云端化 → 迁移完成前不删本地数据。
5. 开发端导出审核包后可**一键上传**，返回 `https://3d.propanda.cn/reviews/xxx.html` 链接并支持复制；保留独立「上传」按钮重传旧包。
6. 上传的审核包与 GLB 模型经 Nginx 静态直出，在线预览行为与 `file://` 双击一致。

**非目标**

- 不做多人账号体系、权限分级（固定 Token 即可，内部工具）。
- 不做并发编辑冲突合并（采用最后写入胜出，P1 再考虑时间戳提示）。
- 不改审核端离线运行时与导出格式（schemaVersion / JSON 契约不变）。
- 不做服务器端渲染或数据库（纯文件落盘）。
- 不做审核结果在线回传（审核员导出后仍走线下回传，后续可选）。

## 3. 设计原则

1. **同域直连**：开发端 dist 与 `/api/` 同在 `3d.propanda.cn` 下，零 CORS；本地 dev 用 Vite proxy 转发，后端不开 CORS。
2. **本地优先**：云端是持久化备份与跨设备同步通道，不是运行时依赖；断网可继续编辑。
3. **模型与项目分离**：GLB 按内容 hash 落盘去重，项目 JSON 轻量化，只存 `{hash, fileName, size}` 引用。
4. **契约不变**：审核包导出仍走「GLB 内嵌自包含」逻辑，仅模型来源从「本地 File/base64」扩展出「服务器 URL」一路。
5. **运维可回滚**：服务端每次改动留时间戳备份，延续 `G:\项目\服务器部署` 既有惯例。

## 4. 总体架构

```text
浏览器（任意设备）
  开发端 https://3d.propanda.cn/
    │  fetch（同域，header: X-ModelQA-Token）
    ▼
Nginx :8444（/etc/nginx/conf.d/model-review-tool.conf）
  location /api/     → 反代 127.0.0.1:8445（资源服务）
  location /reviews/ → 静态 autoindex（在线预览列表）
  location /data/    → 静态（models/*.glb 直出，供开发端加载）
  其余               → /var/www/model-review-tool/（开发端 dist）
    │
    ▼
modelqa-data.service（Python 3 标准库，127.0.0.1:8445）
  落盘 /var/www/modelqa-data/
    ├─ projects/<id>.json          # 项目草稿
    ├─ models/<hash>.glb           # 模型二进制（hash 去重）
    └─ reviews/<名称>-<时间戳>.html # 在线预览审核包
```

## 5. 服务端方案（P0）

### 5.1 资源服务 `modelqa-data-server.py`

实现方式：`http.server.ThreadingHTTPServer` + `BaseHTTPRequestHandler`，单文件，零第三方依赖。

**接口定义**

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/projects` | — | `{"projects":[{"id","name","updatedAt"},...]}` |
| GET | `/api/projects/<id>` | — | 项目 JSON 原文 |
| PUT | `/api/projects/<id>` | 项目 JSON（含 `name`） | `{"ok":true,"updatedAt"}` |
| DELETE | `/api/projects/<id>` | — | `{"ok":true}`（同时解除模型引用，不删 GLB） |
| POST | `/api/models` | body = GLB 二进制 | `{"hash","url":"/data/models/<hash>.glb","dedup":true|false}` |
| GET | `/api/models` | — | `{"models":[{"hash","fileName","size","uploadedAt"},...]}`（读 `models-index.json`） |
| POST | `/api/upload` | body = 审核包 HTML 全文，header `X-Filename` | `{"url":"https://3d.propanda.cn/reviews/<名>-<ts>.html"}` |
| GET | `/api/health` | — | `{"ok":true}` |

**规则**

- 鉴权：除 `GET /api/health` 外，全部接口校验 `X-ModelQA-Token`，与配置文件不符返回 401。Token 存 `/var/www/modelqa-data/server-config.json`（权限 600）。
- 模型去重：服务端计算 SHA-256，已存在则直接返回 `dedup:true`，不重复落盘。
- 模型索引：落盘时同步维护 `/var/www/modelqa-data/models-index.json`（`hash → {fileName, size, uploadedAt}`），供 `GET /api/models` 列表还原文件名；写入采用「读-改-原子替换」避免并发损坏。
- 项目 id：前端生成（时间戳 + 随机串），服务端只按文件名落盘；id 与文件名做白名单清洗（`[A-Za-z0-9_-]`），防路径穿越。
- 上传审核包命名：`<X-Filename 清洗>-<YYYYMMDD-HHmmss>.html`，同名自动加序号，不覆盖。
- 体积限制：请求体上限 200MB，超限返回 413。
- 日志：写 `/var/www/modelqa-data/server.log`（轮转：大于 10MB 改名 `.1`）。

### 5.2 Nginx 配置增量

`/etc/nginx/conf.d/model-review-tool.conf`（8444 站点）追加：

```nginx
client_max_body_size 200m;

location /api/ {
    proxy_pass http://127.0.0.1:8445;
    proxy_set_header Host $host;
    proxy_read_timeout 300s;
    client_body_buffer_size 10m;
}
location /reviews/ {
    alias /var/www/modelqa-data/reviews/;
    autoindex on;
    add_header Cache-Control "no-cache";
}
location /data/ {
    alias /var/www/modelqa-data/;
    add_header Cache-Control "public, max-age=31536000, immutable";
}
```

说明：`/data/models/<hash>.glb` 内容寻址不变，可强缓存；`/reviews/` 列表不缓存。

### 5.3 systemd 与部署脚本

- 单元文件 `/etc/systemd/system/modelqa-data.service`：`ExecStart=/usr/bin/python3 /opt/modelqa-data/modelqa-data-server.py`，`Restart=always`，监听 `127.0.0.1:8445`。
- 运维脚本新增至 `G:\项目\服务器部署\`（沿用现有 paramiko/ssh 脚本风格，凭据不写死在文档）：
  - `deploy_data_service.py`：上传服务文件、写 config、装 systemd、改 Nginx、`nginx -t` 后 reload、`curl /api/health` 验证；
  - 改动 Nginx/systemd 前自动留 `backup_*.<时间戳>` 本地副本（惯例不变）。

## 6. 开发端方案（P1）

### 6.1 新增模块 `tool/src/editor/cloud-sync.js`

开发端唯一的云端通信层，`main-implementation.js` 不直接 fetch：

```js
// 职责与导出（示意）
export const cloud = {
  available,                 // 是否配置了 API 基址（构建注入，恒为同域 /api）
  listProjects,              // GET /api/projects
  loadProject(id),           // GET /api/projects/<id>
  saveProject(id, json),     // PUT（防抖在调用方）
  deleteProject(id),
  listModels,                // GET /api/models → 云端模型库列表
  uploadModel(arrayBuffer),  // POST /api/models → {hash,url}
  fetchModel(url),           // GET /data/models/<hash>.glb → ArrayBuffer
  uploadReviewPackage(html, filename), // POST /api/upload → {url}
};
// Token 经 Vite define 注入：__CLOUD_TOKEN__（define 常量，不入源码仓库，见 6.4）
```

### 6.2 草稿 → 云端项目改造（`main-implementation.js`）

| 现有机制 | 改造 |
|---|---|
| 多槽草稿存 localStorage（上限 10 条，防抖自动保存） | 结构保留；保存策略改双写：本地立即写，`setTimeout` 防抖 3s 后 `saveProject`；上限放开至 50 |
| 草稿内嵌模型 base64 | 草稿 JSON 只存 `{hash, fileName, size}` 引用；base64 仅在「未同步的本地新模型」临时保留，上传成功后替换为引用 |
| 启动恢复：读 localStorage | 恢复后后台 `listProjects` 对账：云端有而本地无的槽位补拉（含 `fetchModel`）；本地有而云端无的（离线期间新建）推送 |
| UI「草稿列表 / 新建草稿 / 另存为」 | 文案改「项目列表 / 新建项目 / 另存为」；每条显示同步徽标（已同步 / 待同步 / 离线）；顶栏「立即保存」保留并追加「同步到云端」语义 |
| 删除项目 | 双删：本地 key + `deleteProject`；云端失败时保留云端，徽标「待清理」，不阻塞 UI |

**模型加载路径扩展**（编辑端 Three.js 加载处）：

```text
本地拖入 File ──► ArrayBuffer（原逻辑）
同步恢复/换设备 ──► fetchModel("/data/models/<hash>.glb")
导出审核包 ──► 模型源三选一：本地 File / base64 / 服务器 URL fetch 后内嵌
```

导出逻辑本身不改：拿到 ArrayBuffer 后走既有 base64 内嵌流程。

### 6.3 旧数据迁移（一次性）

1. 启动时检测 `localStorage` 旧草稿（沿用现有旧 key 迁移探测点，版本标记 `cloudMigrated: true`）。
2. 逐槽执行：`base64Chunks` 解码 → `uploadModel` → 引用替换 → `saveProject`。
3. 任一步失败：该槽标记「待迁移」，本地数据**不动**，下次启动重试；全部成功才写迁移完成标记。
4. 迁移过程 UI：顶栏一次性 toast「正在同步 N 个本地项目到云端…」，不阻塞编辑。

### 6.4 配置与安全

- `__CLOUD_TOKEN__` 与 `__CLOUD_BASE__` 经 `vite.config` `define` 注入：值读 `tool/.env.local`（gitignore，提供 `.env.example` 占位）。生产 dist 构建时内置 Token——内部工具可接受，文档明示「Token 前端可见，勿用于公网强隔离」。
- 本地 dev：`vite.config` 加 `server.proxy`：`/api`、`/data`、`/reviews` → `https://3d.propanda.cn`（`changeOrigin`，避免后端开 CORS）。

## 7. 在线预览链路（P2，依赖 P0）

1. 开发端导出「单 HTML」审核包（既有逻辑，产物为字符串/Uint8Array）。
2. `uploadReviewPackage(html, "课程名")` → 服务端落盘 `/reviews/课程名-<ts>.html` → 返回 URL。
3. 开发端 toast 展示完整链接 + 复制；审核员手机/PC 浏览器打开即审（secure context 下 `showDirectoryPicker`/IndexedDB/fflate 均可用，行为与 `file://` 一致）。
4. `https://3d.propanda.cn/reviews/` 为 autoindex 列表，作为简易入口。

## 9. 边界与风险

| 风险 | 处理 |
|---|---|
| Token 内置于前端可被提取 | 可接受（内部工具）；`/api/` 不开放写权限给匿名，风险面=知道 Token 的人可覆盖项目数据；后续可换短期签名 |
| 并发双开编辑互相覆盖 | 最后写入胜出；草稿条目展示 `updatedAt`；P1 视需要加「云端较新」提示 |
| 大 GLB 上传超时/中断 | 200MB 上限 + 300s 超时；上传失败徽标「待同步」自动重试（指数退避，最多 3 次） |
| 服务器磁盘增长 | GLB hash 去重；`deploy_data_service.py` 附带 `--backup` 打包 `/var/www/modelqa-data` 到本地 |
| 迁移中途失败 | 本地数据永不删除；逐槽重试；迁移标记原子写入 |
| Nginx 配置错误影响 Xray 分流 | 改前自动备份 + `nginx -t` 通过才 reload；回滚方案沿用服务器部署 README |
| `/reviews/` 链接外泄即可访问 | P0 接受；P1 可选 Basic Auth（一段 location 配置，预留） |

## 12. 验证方式

1. P0：`deploy_data_service.py` 执行后按验收清单逐条 curl/浏览器验证。
