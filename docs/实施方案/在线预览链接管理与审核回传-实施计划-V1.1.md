> 背景先读：`docs/apps-code-map.md`、`docs/实施方案/开发端云端持久化与审核包在线托管-实施计划-V1.0.md`。

## 1. 背景与讨论结论

| 讨论点 | 结论 |
|---|---|
| 链接如何管理 | 以服务端 `/api/reviews/list` 为唯一数据源，开发端出管理面板，不在 localStorage 另记一份 |
| 链接名称过长 | 文件名短码化（课程码-MMDD-HHmm.html），页面 `<title>` 保留课程全称；课程码对照表配置化 |
| 能否删除 | 能，必须走服务端接口；软删除（移入 `reviews/_archive/`）；行内二次确认（不依赖浏览器 confirm） |
| 审核端如何回传 | 审核端在线页加「回传审核结果」按钮，已审 HTML 直接 `POST /api/reviews/submit` → 服务端落盘 `<原名>-已审.html` |
| 回传用什么鉴权 | **不能复用开发端 Token**（会嵌进自包含 HTML，等于公开删库权限）；新增权限极小的**回传 Token**（仅能 POST submit），打包时注入审核包 payload |
| 已审/未审怎么区分 | **不新增独立面板模块**：开发端面板做未审/已审两个页签；状态由文件名派生（存在对应 `-已审` 文件即已审），零额外存储、无同步问题 |
| 离线兜底 | 审核员 `file://` 打开或断网时隐藏回传按钮，线下导出 ZIP 回传老路保留——回传是增强不是唯一通道 |

## 2. 目标与非目标

**目标**

1. 服务端：`GET /api/reviews/list`（含 `reviewed` 字段）、`DELETE /api/reviews/<name>`（软删除）、`POST /api/reviews/submit`（回传 Token 鉴权）。
2. 审核端：导出区加「回传审核结果」按钮（仅在线托管 + payload 含回传 Token 时显示）。
3. 开发端：「在线预览链接」管理面板，未审/已审两页签，支持打开/复制/删除。
4. 文件名短码化：`<课程码>-<MMDD>-<HHmm>.html`，页面标题保留课程全称。

**非目标**

- 不做硬删除/回收站 UI（`_archive/` 手动清理）。
- 不做账号/权限体系（沿用固定 Token + 新增回传 Token，两个静态 Token）。
- 不做已审版覆盖未审版（两份并存，开发端以已审版为准，未审版可手动删）。
- 不改审核端离线运行时的记录/导出格式（schemaVersion / JSON 契约不变）。
- 存量已发链接不强改：旧包 payload 无回传 Token，回传按钮不出现，走线下兜底。

## 3. 服务端改动（`G:\项目\服务器部署\modelqa-data-server.py`）

沿用现有 handler 结构（`do_GET` / `do_POST` / `do_DELETE` 均已有），配置 `server-config.json` 增加一个 `submitToken` 字段：

| 方法 | 路径 | 鉴权 | 请求 | 响应 | 说明 |
|---|---|---|---|---|---|
| GET | `/api/reviews/list` | 开发端 Token | — | `{reviews:[{name,size,uploadedAt,url,reviewed}]}` | 扫 `REVIEWS_DIR` 顶层 `*.html`；`reviewed` = 存在 `<name 去 .html>-已审.html`；已审文件本身 `reviewed:true` 且不重复计入其未审条目 |
| DELETE | `/api/reviews/<name>` | 开发端 Token | — | `{ok:true}` | 软删除：`os.rename` → `reviews/_archive/<name>` |
| POST | `/api/reviews/submit` | **回传 Token** | body=已审 HTML 全文，header `X-Orig-Filename`（可选） | `{ok:true,url}` | 落盘为 `<原名>-已审.html`（原名取 header，无则用 body 内时间戳命名）；重传覆盖；同样的文件名白名单清洗 |

**安全要求**

- name/origFilename 一律白名单校验（`[\w\-（）\u4e00-\u9fa5]+\.html` 或清洗后匹配），仅顶层、禁 `_archive`，杜绝 `../` 穿越（照抄现有 id 清洗逻辑）。
- `submitToken` 仅允许 `POST /api/reviews/submit`，其余一律 401。
- 上传大小沿用现有 200MB 上限逻辑（413）。

**Nginx 注意**：`_archive/` 目录不对外直出/autoindex，需在站点配置排除（部署脚本冒烟项验证 404）。

部署：本地冒烟（参考 `_archive/local_smoke_data_server.py`）→ `deploy_data_service_update.py` → 服务器侧时间戳备份（既有惯例）。

## 4. 开发端改动（本仓库）

### 4.1 `tool/src/editor/cloud-sync.js`

```js
listReviews()               // GET /api/reviews/list
deleteReview(name)          // DELETE /api/reviews/<encodeURIComponent(name)>
```

dev 无需改 Vite proxy（`/api` 已转发）。

### 4.2 `tool/src/editor/main-implementation.js`

- 「在线预览链接」面板：两页签 **未审核 / 已审核**（前端按 `reviewed` 过滤，按时间倒序），每条含 文件名/时间/大小 + 「打开」「复制」「删除」。
- 删除用行内二次确认（首点变红「确认删除」+ 3s 超时还原，同项目删除方案），文案明示「链接将立即失效」。
- 云端不可用（无 Token/请求失败）时禁用面板入口。
- 面板数据一律服务端拉取，不写本地记录。

### 4.3 回传 Token 注入（打包链路）

- `reviewerHtml(data)` 的 payload 增加字段（如 `data.submitToken`），值来自 vite define `__CLOUD_SUBMIT_TOKEN__`（`.env.local` 新增，服务端 `submitToken` 同值）。
- 仅在线托管场景有意义；`file://` 打开时 runtime 检测 `location.protocol` 不显示回传按钮。

## 5. 审核端改动（`tool/src/reviewer/reviewer-implementation.js`）

- 导出区新增「回传审核结果」按钮，显示条件：`payload.submitToken` 存在 且 `location.protocol` 为 http/https。
- 行为：当前已审数据走现有导出逻辑生成 HTML（复用 runtime 自包含导出）→ `POST /api/reviews/submit`（header `X-Orig-Filename: <当前包文件名>`）→ toast「已回传，开发端可见」；失败可重试。
- 原有「导出已审 HTML/ZIP」按钮不动，作为离线兜底。

## 6. 文件名短码化（独立可后置）

- 课程码对照表配置化（本地配置文件或项目字段）：课程全称 ↔ 短码。
- 导出/上传文件名模板：`${课程码}-${MMDD}-${HHmm}`；`<title>` = `${project.name} · 审核报告 ${日期}`。

## 8. 风险与提示

1. **删除即失效**：已发链接删除后立即 404；删除只影响开发端 Token 持有者操作，审核员无删权。
2. **回传 Token 泄露面**：拿到审核链接的人可重复回传（覆盖 `-已审` 文件），可接受；但绝不能放宽到其他接口。
3. **路径安全**：list/delete/submit 三处文件名均白名单校验，杜绝穿越。
4. **存量包无回传**：V1.1 上线前已发的链接不含回传 Token，只能线下回传，不做兼容。
5. **归档膨胀**：`_archive/` 手动清理；Nginx 必须排除直出。
6. **回滚**：服务端改动前时间戳备份，可整体回退。
