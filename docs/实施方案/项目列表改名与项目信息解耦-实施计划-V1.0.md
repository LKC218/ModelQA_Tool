# 项目列表改名与项目信息解耦实施方案

> 版本：V1.0 ｜ 日期：2026-09-12 ｜ 状态：已实施并验证上线（E2E 11/11 PASS，MD5 一致）

## 1. 背景与根因

用户反馈「项目信息丢失」，排查确认三种现象与根因：

| 现象 | 根因 |
|---|---|
| 项目名被改名污染 | `renameDraft` 把列表标签写进 `payload.project.name/displayTitle`（连带活动项目表单），列表改名 = 永久覆盖项目身份数据。「（云端恢复）（已审核）」这类后缀名经全 git 历史 `-S` 搜索确认非任何版本代码生成，是改名入口写入的 |
| 出现重复项目 | 云端对账「云端有本地无 → 按 remote.id 建新槽」+ 各设备本地草稿并存 → 同一逻辑项目占两个槽 |
| 模型/审核记录丢失 | 见 §4 已知问题（本轮未改，属独立大项） |

## 2. 修复内容（方案 A：解耦）

| 文件 | 改动 |
|---|---|
| `tool/src/editor/main-implementation.js` | ① `renameDraft`：只改 `meta.name` + 标记 `meta.customName=true`，不再碰 `payload.project` 与项目信息表单；② `writeDraft`：仅当 `!meta.customName` 时列表名跟随项目名，新建槽 `customName: !!name`；③ `copyDraft`：副本标签标 `customName=true`（否则切入副本保存后「-副本」标签被项目名覆盖）；④ `reconcileCloud` 云端拉回条目 `customName=true`（尊重云端名）；⑤ 项目列表项新增 `.draft-item-sub` 副行，显示项目设置中的真实项目标题（识别被改名项目与重复项目） |
| `tool/src/editor/styles.css` | `.draft-item-sub` 副行样式（小字、截断） |

云端 name 本就取 `meta.name` 推送（`pushProjectToCloud`），与项目字段分离，解耦后云端列表名照常同步。

## 3. 测试

探针 `tool/scripts/smoke/probes/probe-project-rename.cjs`（拦截 `/api/**` 走离线，不污染云端）：11/11 PASS，零 pageerror。
- 初始列表名跟随项目名；改名后 `meta.name=新标签`、`customName=true`、**payload.project.name/displayTitle 不变**；
- 列表副行显示真实项目标题；改名按钮提示「仅列表标签，不改项目信息」；
- 后续自动保存：customName 保持（列表名不被项目名回写），项目字段照常保存（version=V9.9）。

## 4. 已知问题（本轮未修，待立项）

1. **模型丢失根因**：GLB 二进制只存内存 File + 云端模型库（按 hash），草稿 payload 仅存元数据与 `modelCloudRefs`。导入时若云端不可用/上传失败，切项目或刷新后 GLB 永久丢失（只剩待恢复元数据）。另有已记录的「云端恢复 vs 手动导入」竞态。
2. **审核记录分裂**：同一项目占两个槽时，审核记录写在后使用的槽里，另一槽看起来"丢了"；`pruneDraftList` 50 条上限会静默删除最旧槽。
3. **云端 last-write-wins**：`pushProjectToCloud` 无条件推平本地 payload，本地陈旧数据可覆盖云端较新数据（跨设备场景）。需要 updatedAt 比对或合并策略，复杂度较高。
4. 「（已审核）」状态建议做成列表徽标（取 `/api/reviews/list` 的 reviewed 字段关联），不烧进名字。
