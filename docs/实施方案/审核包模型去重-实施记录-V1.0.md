# 审核包模型去重（hash 共享池）- 实施记录 V1.0

> 2026-09-14 实施，探针 22/22 通过（`tool/scripts/smoke/probes/probe-e2e-dedup.cjs`）。

## 背景

同一 GLB 被多个课程复用导入时：持久层（云端模型库按 SHA-256 去重）与项目草稿（仅存 `{hash,url,size}` 引用）本无冗余；但**审核包导出**环节按模型记录逐份内嵌/写入文件，同内容文件在包内出现 N 份（base64 还膨胀 33%），逼近单 HTML 20MB 上限。本方案使导出包中同内容文件仅存一份。

## 数据结构（schemaVersion 2 → 3）

```
v2: project.models[] 每项自带 base64Chunks（重复嵌入）
v3: 顶层 modelData: [{ key: <sha256-hex>, fileRef: "<原名>-<key前8>.glb", base64Chunks }]  ← 每唯一内容一份
    project.models[] 每项 { ..., dataKey: key, fileRef }   ← 引用；不再携带 base64Chunks
```

- key 来源优先级：`modelCloudRefs[modelId].hash`（云端库引用，与服务端 `hashlib.sha256` 同算法）→ 客户端 `crypto.subtle.digest('SHA-256')` 自算（离线兜底）→ subtle 不可用时退化为 `model-<modelId>`（行为等同 v2，不报错）。
- 派生字段（dataKey/fileRef/modelData）只存在于导出产物，**不回写 state / draft / 云端项目 JSON**（探针断言保障）。

## 代码改动

| 文件 | 改动 |
|------|------|
| `tool/src/editor/main-implementation.js` | 新增 `sha256Hex()` / `buildContentIndex()`；`payload()` 升 v3（inline 时 modelData 携 base64Chunks，models 携 dataKey/fileRef）；`exportZip()` 改为按唯一 key 写 `models/<fileRef>` 一份 |
| `tool/src/reviewer/reviewer-implementation.js` | 新增 `modelChunks()`（v3 池优先 / v2 旧字段兼容）；`loadModel` inline 取池、folder 按 `fileRef || fileName` 找文件；`canExportReviewedHtml/Zip` 判定改 `modelChunks`；`collectModelBinaries` 按 fileRef 收集（同 key 一份，顺带修复同名覆盖隐患）；`buildReviewedPayload` **透传 modelData**（已审 HTML 必须随池）；`buildReviewedZipPayload` 剥离 modelData（ZIP 已有物理文件，避免冗余） |

## 兼容矩阵

| 场景 | 结论 |
|------|------|
| v3 包 → 新审核端（随包分发） | 主路径 ✓ |
| v2 旧包 → 新审核端 | `modelChunks` fallback `base64Chunks` / files 按 `fileName` ✓（探针回归通过） |
| v3 包 → 旧审核端 | 不存在真实场景（审核包自包含一次性分发，runtime 与 payload 同次导出） |
| 云端项目 JSON / 模型库 / 回传链路 | 不涉及（modelCloud 引用机制、issues JSON 均不动） |
| 已审 ZIP 解包再拖入 | loadDirectory mode:'folder'，走 `files.get(fileRef)` ✓ |

## ZIP 内文件名变化

`models/<原名>.glb` → `models/<原名>-<key前8位>.glb`（同内容多课程引用合并为一份）。人工解包可读性保留原名前缀。
