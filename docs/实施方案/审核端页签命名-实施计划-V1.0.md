# 审核端页签命名 实施计划 V1.0

> 本文档自包含，新会话可直接按此执行。  
> 背景先读：`docs/apps-code-map.md`、`docs/工具化/README.md`。  
> 已拍板：审核端浏览器页签兜底名 → **「3D 模型审核」**；已审产物静态页签名 → **「3D 模型审核报告」**。

## 1. 背景与问题

### 1.1 现象

审核端页面在浏览器页签显示「离线模型审核」。「离线」描述的是**部署形态**（无需服务器、可双击打开），对审核者没有信息量；页签上真正该传达的是「这是什么页面、审什么」。

同时，旧命名采用「X（已审）」括号式后缀，在产物已扩展为单 HTML / ZIP / 在线回传三类后，语义不够清晰。

### 1.2 标题的两条独立通路（关键）

浏览器页签与页内顶栏标题**互不相关**：页签由静态 `<title>` 决定，且运行时从不修改；页内顶栏由运行时按项目名覆盖。

| 通路 | 载体 | 写入方 | 是否被运行时覆盖 |
|---|---|---|---|
| 浏览器页签 | 文档 `<title>` | 未审包：编辑端 `main-implementation.js:1031`；已审包：审核端 `reviewer-implementation.js:846` | **否**（全文无 `document.title` 赋值） |
| 页内顶栏标题 | `<h1 id="title">` | 初始值 `reviewer-implementation.js:398` | 是：`:1120`（folder 载入）/ `:1299`（启动初始化） |

```270:270:tool/src/reviewer/reviewer-implementation.js
const $ = (id) => document.getElementById(id);   // $('title') 取的是页内 h1，不是文档标题
```

```846:846:tool/src/reviewer/reviewer-implementation.js
return `<!doctype html><html lang="zh-CN">...<title>${PAGE_TITLE_REVIEWED}</title></head>...`;
```

### 1.3 事实澄清（影响验收预期）

1. `$` 是 `document.getElementById` 的别名（`reviewer-implementation.js:270`），`$('title')` 取的是页内 `<h1 id="title">`，**不是**文档标题；全文无 `document.title` 赋值。
2. 因此**浏览器页签文案 = 静态 `<title>` 字面量，恒定显示、不受项目名影响**：未审包恒为「3D 模型审核」，已审包恒为「3D 模型审核报告」。问题截图里的「离线模型审核」正是编辑端模板字面量。
3. 页内顶栏 `<h1 id="title">` 走 `displayTitle → name → 兜底`：有名称显示项目名，无名称显示「3D 模型审核」。
4. 由此，P1「已审标识是否常驻页签」**自动满足，无需实现**——页签本就恒定，不存在被覆盖的问题。

> 实施期更正：本计划初稿曾判断「运行时用项目名覆盖页签」，该结论有误（把 `$('title')` 误认为文档标题）。上述结论已由端到端探针实测确认，见 §11。

## 2. 目标与非目标

**目标**

1. 未审产物（编辑端单 HTML、编辑端 ZIP 内 `审核器.html`）默认页签为「3D 模型审核」。
2. 已审产物（审核端已审 HTML、已审 ZIP 内 `审核器.html`）默认页签为「3D 模型审核报告」。
3. 运行时标题优先级 `displayTitle → name → 兜底` **保持不变**。
4. 兜底文案收敛为**单一常量**，避免同一字面量散落 4 处。
5. 不新增文件、不新增依赖、不改 ZIP / JSON 数据结构。

**非目标**

- 不改 ZIP 内 `审核器.html` 文件名（ZIP 结构契约，`docs/工具化/README.md` 及多份实施计划已固化引用）。
- 不改下载文件名规则（`<项目名>-已审-<时间戳>.html/.zip`、`<项目名>-审核包.zip`）。
- 不改编辑端自身页面标题（编辑器页签）。
- 不改 `tool/src/reviewer/reviewer-entry.js` 内已注释的旧版运行时（死代码；esbuild 以 `legalComments: 'none'` 打包，注释中的 3 处旧文案会被剥离，不产出到任何产物）。
- 不回溯修改 `tool/output/export-reviewed/` 下历史验收产物。

## 3. 命名规范（拍板）

| 场景 | 页签文案 | 来源 |
|---|---|---|
| 未审包，项目有名称 | `4. 模拟电路实训室` | `displayTitle → name`（不变） |
| 未审包，项目无名称 / 加载前 | **`3D 模型审核`** | 新增常量 `PAGE_TITLE` |
| 已审包静态 title | **`3D 模型审核报告`** | 新增常量 `PAGE_TITLE_REVIEWED` |
| 已审包，运行时覆盖后 | 仍为项目名（现状不变） | 见 §7 P1 决策点 |
| 本地预览页 `public/reviewer-preview.html` | `审核端预览（样例数据）` | **不改**（非产出的审核包） |

命名理由：与 `README.md` 产品定位「3D 模型项目审核工具」一致；「报告」比「（已审）」更贴近交付物接收方（收到已审包的人）的阅读预期；字数最短，窄页签下不易截断。

## 4. 技术方案

### 4.1 新增常量（`tool/src/reviewer/reviewer-implementation.js`，紧邻 `FOLDER_HTML_HINT`）

遵循该文件既有常量风格（文件级 `UPPER_SNAKE`）：

```js
/* 页签兜底名：项目未填写 displayTitle/name 时使用（见 docs/实施方案/审核端页签命名-实施计划-V1.0.md） */
const PAGE_TITLE = '3D 模型审核';
/* 已审产物静态页签名：仅 JS 执行前可见，运行时仍以项目名覆盖 */
const PAGE_TITLE_REVIEWED = '3D 模型审核报告';
```

### 4.2 五处文案替换

| 序号 | 文件:行 | 现状 | 改为 |
|---|---|---|---|
| 1 | `reviewer-implementation.js:398` | `<h1 id="title">离线模型审核</h1>`（页内顶栏初始值） | `` `<h1 id="title">${PAGE_TITLE}</h1>` `` |
| 2 | `reviewer-implementation.js:846` | `<title>离线模型审核（已审）</title>` | `` `<title>${PAGE_TITLE_REVIEWED}</title>` `` |
| 3 | `reviewer-implementation.js:1120` | `\|\| '离线模型审核'` | `\|\| PAGE_TITLE` |
| 4 | `reviewer-implementation.js:1299` | `\|\| '离线模型审核'` | `\|\| PAGE_TITLE` |
| 5 | `editor/main-implementation.js:1031` | `<title>离线模型审核</title>` | `<title>3D 模型审核</title>` |

第 1 处为**实施期补充发现**：页内顶栏 `<h1 id="title">` 与浏览器页签同源同文案，页面加载瞬间可见，属同一命名问题，遂一并纳入 P0（原计划遗漏）。

**关于第 5 处为何写字面量而非引用常量**：编辑端通过 `import reviewerRuntime from '../generated/reviewer-runtime.js?raw'` 引入运行时的**字符串**；若再 `import` 审核端模块取常量，Vite 会将整份运行时作为可执行代码重复打进编辑端 bundle（体积与副作用双重代价）。故编辑端保持字面量，并在模板前加一行注释指向常量定义处。

### 4.3 冒烟断言收紧（可选但建议）

`tool/scripts/smoke/smoke-export-reviewed.mjs:84`：

```js
hasReviewedTitle: htmlText.includes('已审'),
```

该断言是**弱断言**——导出 HTML 内嵌的运行时源码里含大量「已审」文案（导出按钮、footer 状态行），即使标题改为「3D 模型审核报告」也恒为真，无法真正校验标题。建议收紧为：

```js
hasReviewedTitle: htmlText.includes('<title>3D 模型审核报告</title>'),
```

`result.json` 的 `pass` 判定引用同名键（同文件 `:137`），键名不变，无需改动。若工程师希望改动最小化，本项可跳过（不影响功能，仅降低校验有效性）。

### 4.4 构建链路（必须）

`tool/src/generated/reviewer-runtime.js` 由 esbuild 从 `reviewer-entry.js` 打包生成（入口 `import './reviewer-implementation.js'`）：

```
npm run prepare:reviewer   # 单独重建运行时（dev/build 已前置自动执行）
npm run build              # 重建 dist/index.html、dist/reviewer-preview.html
```

## 6. 边界与风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 已审标识被运行时覆盖 | 「报告」字样只在加载前可见，用户可能以为改动未生效 | 验收时明确按 §1.3 预期核对；如需常驻走 §7 P1 |
| 页签文案与项目名并列时长度 | 若 P1 采用「项目名 · 3D 模型审核报告」，窄屏页签更易截断 | P1 采用时用中点分隔，并把工具名放后段（截断优先丢工具名） |
| 编辑端 ZIP 内 `审核器.html` 未同步 | 同一改动点覆盖单 HTML 与 ZIP 双产物（同走 `reviewerHtml`），遗漏风险低 | 验收同时抽查两种产物 |
| 旧产物行为变化 | 无——历史 `output/export-reviewed/*.html` 不重建 | 不动历史文件 |
| 常量引入位置 | 若常量放在 `reviewer-implementation.js` 之外，编辑端无法零成本复用 | 保持文件级常量，编辑端用字面量 + 注释指引 |

**回滚**：改动为纯字符串替换，回滚即 `git checkout -- tool/src/reviewer/reviewer-implementation.js tool/src/editor/main-implementation.js tool/scripts/smoke/smoke-export-reviewed.mjs` 后重新构建。

### P1（无需实现）

若未来产品希望在页签中**同时**体现项目名（例：`模拟电路实训室 · 3D 模型审核报告`），才需在导出时把项目名写进静态 `<title>`。写入点两处，均可取到 `data.project`：

```js
/* reviewer-implementation.js: reviewHtmlShell 内 */
<title>${data?.project?.displayTitle || data?.project?.name || ''}${data?.project ? ' · ' : ''}${PAGE_TITLE_REVIEWED}</title>
```

编辑端 `reviewerHtml(data)` 同理。属增强，非缺陷修复。
