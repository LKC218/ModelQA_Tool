# 审核端功能引导可用性细化 实施计划 V1.1

> 本文档自包含，新会话可直接按此执行。  
> 背景先读：`docs/apps-code-map.md`、`docs/实施方案/审核端功能引导-实施计划-V1.0.md`。  
> 决策：在 V1.0（7 步 A 方案）基础上，落地 **主按钮改「下一步」** 与 **目标自动滚入视口**；不改步骤数与数据契约。

## 1. 背景与问题

| 现状 | 说明 |
|---|---|
| 主按钮文案 | 中段步骤为「开始审核」，与真实审核动作抢语义；门禁未过时更像产品 CTA |
| 可滚动侧栏 | 右栏「问题记录 / 模型结论」等目标常被裁切；挖洞对准的是可视矩形，目标可能在滚动区外 |
| 已交付基线 | 7 步导览、四边挖洞、第 1 步导入门禁、`an_reviewer_onboarding_v2`、`an-reviewer:package-loaded` 自动进第 2 步 |

讨论结论：

1. 中段主按钮统一为 **「下一步」**，末步保持 **「完成」**；不用「开始审核 / 继续」。
2. 步骤切换时对 target **先滚动进视再量矩形**；引导内用瞬时滚动，避免与高亮动画抢单。
3. 不做「用户滚动时实时重算洞」的复杂监听；仅 **步进时滚一次 + resize 重算**。

## 2. 目标与非目标

**目标**

1. 7 步主按钮：第 1–6 步显示「下一步」，第 7 步显示「完成」。
2. 右栏/左树等可滚区域内，步骤高亮目标可见，不被 sidebar 裁切。
3. 第 1 步导入门禁、自动进下一步、跳过/完成记忆行为保持不变。

**非目标**

- 不增删步骤、不改 target 选择语义（仅滚动与量测时机）。
- 不实现滚动过程中实时跟随高亮。
- 不改 `review.byModel`、导出 ZIP/HTML/JSON 契约。
- 不引入外部滚动库。

## 3. 交互与文案规格

### 3.1 主按钮

| 步 | 按钮文案 | 行为 |
|---|---|---|
| 1–6 | **下一步** | 门禁未过则禁用；通过则 `go(index+1)` |
| 7 | **完成** | 关闭本轮（可写 `an_reviewer_onboarding_v2 = done`，但不再据此跳过下次自动弹出） |

- 门禁提示句保持：「请先拖入或选择审核包，加载成功后自动进入下一步。」
- 不再使用「开始审核」作为导览主按钮。

### 3.2 自动滚入视口

触发时机：`openAt` / `go` / `onResize` 中 `render` 之前或量测之前。

流程：

```text
resolveTarget(el)
  → ensureTargetVisible(el)
       ├─ el.scrollIntoView({ block: 'center', inline: 'nearest', behavior: 'auto' })
       └─ 可选：向上找 overflow 祖先并 scrollIntoView（默认依赖 scrollIntoView 冒泡即可）
  → 等 2 帧 rAF（或 scrollend）
  → getBoundingClientRect → 四边遮罩 / 描边 / 浮层定位
```

要点：

1. `behavior: 'auto'`（瞬时），不要 `smooth`（避免和 240ms 高亮 transition 抢时间）。
2. 高亮 `pad` 从 6px 调到 **10px**，减少贴边/被 sticky 压住。
3. 「记问题 / 定结论」继续高亮 **panel**；若 panel 过高导致洞仍裁切，可回退为高亮 **表单区**（`#issue-status` / `#model-status` 父级 field-stack）——实现时以「目标完整进入视口」为验收，不强制改 DOM。

### 3.3 不变项

- 四边 `.onb-panel` 挖洞、洞内可点。
- 第 1 步 `isReady` + `an-reviewer:package-loaded` 自动进第 2 步。
- 跳过不写 done；完成才写 done。
- 「?」重播。

## 4. 技术方案

| 项 | 位置 | 改动 |
|---|---|---|
| 按钮文案 | `tool/src/reviewer/reviewer-onboarding.js` `ONBOARDING_STEPS[].primary` | 1–6 → `下一步`；7 → `完成`（已有完成） |
| 滚动 | 同文件 `ensureTargetVisible` / `render` | 先滚再量；双 rAF |
| pad | 同文件 `holeRect` 默认 pad | `6` → `10` |
| 构建 | `tool/scripts/build/build-reviewer.mjs` | 无需改脚本，重新 `prepare:reviewer` |
| 文档 | 实施计划 V1.0 §5.3、工具化 README、code-map | 按钮与滚动一句同步 |

建议 API 片段：

```js
function ensureTargetVisible(el) {
  if (!el) return Promise.resolve();
  try { el.scrollIntoView({ block: 'center', inline: 'nearest', behavior: 'auto' }); } catch { /* ignore */ }
  return new Promise((resolve) => {
    requestAnimationFrame(() => requestAnimationFrame(resolve));
  });
}
```

`render` 改为 async：`await ensureTargetVisible(found.el)` 后再 `holeRect`。

## 6. 验收清单

1. 导览第 1–6 步主按钮文案为「下一步」，第 7 步为「完成」；无「开始审核」。
2. 第 1 步未加载包时「下一步」禁用；加载后自动进第 2 步。
3. 切到「记问题」「定结论」时，右栏目标进入视口，描边完整可见，不被侧栏裁切。
4. 窗口 resize 后高亮仍对齐。
5. 跳过不写 done；完成写 done；「?」可重播。
6. 导出行为与 V1.0 一致；无外网请求。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| scrollIntoView 滚过头/滚错容器 | `block: 'center'`；验收用右栏真实高度 |
| 双 rAF 在极慢机器仍量到旧位置 | 失败则下一步 `render` 再纠正；不引入 ResizeObserver 轮询 |
| panel 过高洞仍偏大 | 回退高亮表单子区域（见 §3.2） |
